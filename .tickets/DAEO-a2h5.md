# W2-209: releasing on the owner's behalf, slice (a), the patch release

A new feature (the owner, DEC-1223 and DEC-1224 (3); DEC-1219 (6): a new ticket only for a new feature; RB-6 (a)). The
spec is `docs/emergency-2/proposals/RELEASE-ON-BEHALF.md` (approved, DEC-1223); this ticket is **slice (a)** of it:
"the patch rule, the gates, `gov release --patch`, the general re-pin with its rollback, and the push". Slice (b), the
automatic update, is a later slice of the same ticket; its KPI lines are added when W2-207 allows (DEC-1224 (3)). The
ticket extends W2-16 (release) and W2-17 (update) and replaces neither; both stay closed. `src/gov/release/**` and
`src/gov/close/**` are C3: the test designer runs Opus, the engineer Sonnet (the C3 trial, DEC-1222 (2)).

The K lines of the design map here: K1 to S1 and S2, K2 to S5, S6 and F1, K3 to S4 and F3, K4 to S9 and F4, K5 to S3, S7,
F2 and F5, K6 to S10. K7 to K10 are slice (b) and the two W2-17 fixes (landed).

## Problem

Every release so far waited for the owner's hand and a hand-written re-pin script with the version written into it.
Fixes pile up in the meantime. `gov release` refuses everyone but the owner in person (DEC-772), no gate ties a suite run
to a release commit, the re-pin script's post-switch check does not run the hooks every session runs, and nothing reads
whether a release range carries only fixes.

## Approach

All new code in `src/gov/release/`: `patch.py` (P1 to P5, `kind.json`), `gates.py` (G0 to G4, `GateRefused` with the gate
named), `proving.py` (G3), `repin.py` (the general re-pin, `rollback.sh`, `burned`, the push text, `NOTE.md`), the cut in
`src/gov/release/__init__.py` (`build` is reused, never loosened) and `command.py` (the flags `--patch`, `--check`,
`--suite`, `--kept`, `--push`; no new command, DEC-1217). The CLI path never passes a stand-in: the seams are test
functions beside the real ones, as `_release_test` is (an agent cannot pass a gate by a flag). `gov.close.nightly`
gains `--optin`. `governance/project/release-authority.yaml` is committed with `patch_releases: off`.

## Interface (the test designer fixes the remaining names in the acceptance README; the engineer follows them)

- `gov release <X> --patch --check`, `gov release <X> --patch [--suite <file>] [--kept <run folder>] [--push <cmd>]`, run
  from the repository root, `GOV_ROLE=orchestrator`. Errors: `RELEASE_REFUSED` with details `gate` (`G0` to `G4`), `rule`
  (`P1` to `P5`, for G1) and `reason`. `--check` answers `kind: patch` with exit 0, and the refusal `RELEASE_REFUSED`
  (exit as other refusals) with details `kind: bigger`, the rules and the failed ones, for a bigger range.
- The seams, beside the real functions: `release._patch_test(root, version, *, suite=None, rehearse=None, repin=None,
  push=None, caller=...)` for the cut with G3, the re-pin and the push stood in; `proving.rehearse(root, commit, version,
  kept, run=None, judge=None)`; `repin.repin(repo, version, home, *, push=None, check=None)` (home is the scratch
  `$HOME`); `repin.burned(home)`.
- Files: `<home>/.local/share/gov-os/{repin.json, rollback.sh, burned, pin-<C>, wheels/<C>/}`, `<home>/.local/bin/gov`;
  `docs/releases/<X>/{manifest.json, manifest.sha256, kind.json, gates.json, suite.json, NOTE.md}`.
- The authority file: `patch_releases: off|on`, `decision: DEC-1223`, `bake_hours: 4`.

## Rehearsal (the lead's, at the end; the CTO reads it before the authority file goes on)

On a scratch clone of this repository and a scratch `$HOME`: a planted patch passes G1, each planted bigger change is
refused by name, a cut with a planted green record and G3 stood in re-pins in the scratch `$HOME`, and a planted failing
post-pin check rolls back and marks the release burned. Evidence under `docs/plan/wave-2/w2-209-rehearsal/`.
