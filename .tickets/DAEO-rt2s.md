# W2-199: the run-time tool, slice 2: the machine-aware dispatcher and load balancer

**The owner's first priority, 2026-11-18 night: protect the machine and cut usage.** The load reached 194 on 20 CPUs when leads ran pytest outside the slot, and the CTO's full suites reached 54. What holds a run inside the gate today is the scratch shell script `heavy_slot.sh` (outside git, with `heavy_slots.conf`'s `SLOTS=2 x WORKERS=4` and `START_BELOW=12`, machine constants). This slice puts that load admission into the product (`src/gov/resources/slots.py`, `src/gov/dispatch/`), derives its sizes from the detected machine (RT-3), records its waits in the one runtime log (RT-1, RT-7), keeps the GPU from spilling (RT-4) and leaves the script a thin wrapper.

**The sizing, in one line.** A run starts only under `start_below` = 0.6 x CPUs; a started job adds at most `workers x margin` to the load; the slots and workers are sized so that `start_below + slots x workers x margin <= load_limit` (the gate's limit, the CPUs). On the 20-CPU machine the numbers are today's 12 and 2 x 4 (with the margin at 1.0); the RAM term (`verification_peak_bytes` 7.58 GB of 23.5 GB) binds the slot count at 1 until the owner or the configuration file says otherwise.

## Interface

**Admission** (`src/gov/dispatch/admission.py`, called by `gov.resources.slots.run`; imports are lazy so `gov.resources` does not import `gov.dispatch` at load). `START_RATIO = 0.6`. `start_below(cpus)`, `margin()` (from the runtime log's last 20 `ended` events), `room(kind, workers, gpu_need)` returns `(ok, reason, readings)`, `wait_for_room(...)` loops every `GOV_ADMISSION_POLL_S` (default 15, a float) and logs. Readings are `gov.resources.machine.load` (plant `GOV_RESOURCES_LOADAVG`), `nproc` (`GOV_RESOURCES_NPROC`), `gov.dispatch.limits.detect` (RAM from `GOV_RESOURCES_MEMINFO`, the GPU from `nvidia-smi` on `PATH`).

**The runtime log** (`~/.gov-os/runtime/log.jsonl`, `gov.dispatch.runtime.folder()`): one JSON object a line, `{"at": ISO-8601 UTC, "event", "job", "kind", "pid", ...}`; events `ready`, `wait` (`reason`, `room`, `load_1m`, `start_below`), `admitted` (`binding`, `waited_s`), `started` (`slot`, `workers`, `cpus`), `ended` (`code`, `ran_s`, `load_start`, `load_peak`, `workers`, `over_limit_s`, `peak_per_worker`), `nested`, `problem` (`what`), `gpu` (`used_mib`, `total_mib`, `budget_mib`, `spill`, written by the watch pass). A run writes only to this log; only the watch pass writes state.json.

**`gov resources --slot {test,rebuild,measure,embedder,reranker} [--tree T] [--workers N] [--gpu-need-mib N] [--held <slots>] -- CMD...`** as today, plus the kinds, `--held` and the admission; `GOV_HEAVY_PRIORITY`, `GOV_HEAVY_PRIO_CAP` (default 2), `GOV_HEAVY_SLOTS`, `GOV_HEAVY_WORKERS`, `GOV_HEAVY_START_BELOW` read from the environment. A GPU kind with no `--gpu-need-mib` is `RESOURCE_ARGUMENTS_INVALID`. No GPU: the run is refused with the existing gate-shut exit 3 and the refusal text of `limits.gpu_answer`.

**`gov dispatch limits`** prints, besides slice 1's lines, `start_below`, `load_limit` and `margin` with their rules; `limits.derive` gains those keys and its `heavy_slots` and `workers_per_slot` follow KPI 3. **`gov dispatch waits [--over <s>] [--json]`** is KPI 8's; exit 3 on a finding.

**The wrapper** `governance/project/orchestration/tools/heavy_slot.sh`: for the CTO to copy over the live script after the land; the wrapper is not run from the main tree by this branch.

**Records.** Slice 1's `tests/acceptance/W2-121c/test_w2_121c_rt3_limits.py` and `tests/unit/dispatch/test_w2_121c_limits.py` encode the `0.15` and `0.9` formulas: the independent test designer changes the acceptance file to KPI 3's formulas, the engineer the unit one, and the ticket DAEO-5rgj gets one line in its record that W2-199 replaced those two formulas (a fix to a record, not a new ticket).
