## Interface

**The inbox** (`src/gov/dispatch/inbox.py`; the command `src/gov/msg/command.py`). Root `$HOME/.gov-os/inbox/`. An address is a folder `<root>/<address>/` holding `messages.jsonl` (one JSON object a line) and `mark` (the decimal byte offset of the first unread byte; absent means 0). An address matches `^[A-Za-z0-9][A-Za-z0-9._:@+-]{0,127}$` and holds no `..`; another is refused with `MSG_ADDRESS_INVALID` (exit 1, nothing written). A message: `{"id", "at" (UTC ISO-8601, seconds), "from", "to", "kind" ("wake" or "notice"; "watch" only to `runtime`), "text", "data" (an object, optional)}`. Appends hold an exclusive `flock` on `messages.jsonl`; a reader holds one on `mark` and writes it whole. The address `runtime` is the watch pass's own inbox.

- `gov msg send <to> {wake,notice} <text> [--from <address>] [--id <id>] [--data <json object>]`: `--from` defaults to `$GOV_MSG_ADDRESS`, else `unknown`; `--id` to a fresh uuid4 hex. Result `{"sent": true|false, "duplicate": bool, "id", "to"}`; a duplicate id is exit 0.
- `gov msg read [<address>] [--peek]`: text form one line a message, `<at> <kind> <from>: <text>`; `--json` result `{"address", "messages": [...], "mark"}`. No address and no `$GOV_MSG_ADDRESS`: `MSG_ADDRESS_MISSING` (exit 1).
- `gov msg wait [<address>] [--timeout <s>]` (default 540, at most 570): exit 0 with the unread wake messages printed (mark unmoved); exit 124 at the timeout (declared in `EXIT_CODES`).
- `gov msg watch --to <address> --name <label> (--pid <pid> | --exit-file <absolute path> | --transcript <absolute path> [--stall-after <s>])`: one `watch` message to `runtime`, its `data` holding the form, the target (with the pid's boot and start ticks, `gov.resources.machine.identity`, when the process is alive) and `to`; result `{"id"}`.

**The watch pass** (`src/gov/dispatch/runtime.py`; `gov dispatch watch`). Machine-wide; `--root` is not read; no `dispatch.yaml`. The lock: an exclusive non-blocking `flock` on the folder `~/.gov-os/runtime/` itself (held: exit 4, nothing written). Each pass: detect the machine and derive the limits; take the `runtime` inbox's new watch requests (state written before the mark moves); read every `~/.gov-os/machine/sessions/*.json` directly (never through `registry.sessions()`, which clears entries); for each tracked session, watch and transcript, send what is due (wake messages, ids as below); write `state.json` whole; append one JSON line an event to `log.jsonl` (`{"at", "event", ...}`: `pass`, `sent`, `ended`, `stall`, `problem`). state.json: `{"format": 1, "pass": {"at", "ok"}, "machine": {"cpus", "ram_bytes", "gpu_total_mib", "gpu_used_mib", "detected_at"}, "limits": {...}, "sessions": {...}, "watches": {...}, "incidents": {...}, "problems": [...]}`.

Message ids: a session's end `end:<boot>:<pid>:<start_ticks>` (from its registry entry; `end:<pid>:<started>` when it has no identity); a watch's end `watch:<request id>`; a stall `stall:<request id>:<the transcript's mtime, whole seconds>`.

**The limits** (`src/gov/dispatch/limits.py`; `gov dispatch limits [--gpu-need-mib <n>]`, exit 3 for `wait`). Sources, each plantable: CPUs `gov.resources.machine.nproc` (`GOV_RESOURCES_NPROC`); RAM the `MemTotal:` line of `GOV_RESOURCES_MEMINFO` (else `/proc/meminfo`); the GPU `gov.resources.machine.gpu` (`nvidia-smi` on PATH); the measured sizes `verification_peak_bytes` and `working_size_bytes` of `~/.gov-os/machine/gate.json` when present. The ratios are the module's; no CPU count, byte or MiB figure of any machine is in the code or a configuration.

**The launcher** (`src/gov/launch/launcher.py`): the registry entry gains `notify` (the launching process's `$GOV_MSG_ADDRESS`, else `cto`) and `address` (`<role>:<ticket>`); the session's environment gains `GOV_MSG_ADDRESS=<role>:<ticket>`; after the session ends the launcher sends the end message (best effort: a failed send never changes the exit code); before the session starts it prints the RT-8 line, and the launch record gains `rubric`.

**The owner's working assumptions (the CTO's message, 2026-11-17 night), until the owner's decisions in the morning:** T1 (c) the stall check runs from the dispatcher's cron pass (an interim in the Gov OS dispatcher, writing to the CTO's inbox, the last success line; the run-time tool carries the same check, RT-2's stall line); T2 (b) a phone push only for a CTO stall, 60 minutes by day and 2 hours at night, one per stall; T3 (a) no CPU fallback: with no GPU, embedding and reranking jobs are refused and memory is said to be unavailable (RT-3's GPU line). The owner may amend them.
