# W2-55 backfill: proposed tags for every register entry (a proposal; nothing is applied)

A proposal for the owner's review (DEC-791 item 1, DEC-825 items 2 and 4), for the register `docs/DECISION_REGISTER.md` as the commit `b9af0a303538` last changed it (979 entries). Nothing here is written to the register: the orchestrator applies the accepted backfill after the owner accepts it. Every row is a heuristic proposal, and its reason says which rule gave it.

## How this proposal was made

By the script `src/gov/decisions/backfill.py`, run in the project root:
`PYTHONPATH=src python3 -m gov.decisions.backfill > docs/research/W2-55-backfill.md`. It reads `HEAD` only, and the same commit gives the same file. Its rules (the module's docstring states them in full):

- **domain:** the domain of the closed list whose keywords occur most often in the entry, its title counting five times its text (a heuristic: an entry about several domains gets the one with most words);
- **scope:** `kernel` where only files under `template/governance/kernel/` cite the id, `repository` where only the project's prompts and briefs do; otherwise `kernel` where the entry names a kernel path or its title says kernel or skill, else `repository`;
- **lands in:** the files of the scope that cite the id (up to three); where none does, `none` for an entry superseded or done, and its domain's home for an entry in force (a place to write it, not a place that states it yet);
- **status:** `SUPERSEDED by DEC-<n>` where the register marks it superseded or another entry supersedes it by id alone; `done` for the status word DONE; `Changed by: ...` for the entries that change, correct, settle, reverse, withdraw, partly supersede, amend or refine it; else `in force`. One-offs whose action is finished and whose status word is not DONE are not detected: the owner's sample is where they show.
