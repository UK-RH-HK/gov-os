## 1. Scope and rules

1. **Emergency mode (DEC-1239 (3)).** Gov OS's own work lands by the plain path: the change's tests and the merged tree's suites green, a hand merge, recorded. The tools run in full, and are proven, on a scratch repository and in EXAMIN. Nothing here makes Gov OS land through `gov land` until the owner decides (DEC-1239 (4)); that day is called **Day M**. **Every landing, Gov OS's hand merges included, runs the tests the product's impact selection picks, never a hand-picked set** (`gov queue --select`, `gov land --select` after 1-1, lists them) [X-1; DEC-1244]; item 1-0 holds it. **Day S** of an item is the day its verify passes on the scratch repository.
2. **Nothing new starts that is not integration** (DEC-1238 (3)); 0.1.5 stays first and the integration begins when the owner cuts it. EXAMIN's fresh 80, Contract and planning go ahead now, each for the owner's yes; only executing its plan waits for the integrated workflow, and that execution is Phase 6's trial [X-4; changes DEC-1238 (4)].
3. **Each item is a fix or a chore under its owning ticket**, found with `grep -l "^wbs_id: W.-N" .tickets/*.md`; a fix has its failing test first (DEC-1204; golden rule 6). **A new ticket only for a feature the owner has approved.** There are three, and only three:
   - **F-1, the enforcement field** (A-23): item 5-1 [DEC-1238 (1b)]. The task text cites DEC-1241 (1b); the approval is DEC-1238 (1b) (see §6).
   - **F-2, rule 8's first slice** (T-1): item 5-4, slice (a) of decisions by page [DEC-1236 (1); DEC-1242 T-1 (b), R-6 (a)].
   - **F-3, decisions by page, slice (b)**: item 5-5 [DEC-1236 (1); the owner's note on T-1: "it follows as the next slice"].
   Work already approved and open under its own ticket is not new: W2-207 slice 4 (3-1, 3-2), W2-209 slice b (3-9), W2-210 (5-8). A `gov trace` command would be a feature and waits for the owner; chain approach A, as Q-12 (a) settles it, needs none (5-10, 5-11).
4. **The imports feature** (DEC-1222 (1), already approved) is not an item of the phases: it is a fourth stream that joins when EXAMIN's fresh 80 passes, so W1 is fully on by the exit (§3, §4) [X-3]. **Not in this plan:** API keys and other subscription plans (Q-8) and review by a second vendor (Q-10); both are Wave 3 features, built and trialled then, each paid service approved by the owner [DEC-1244].
5. **Every verify says what the step must produce** (its record, its form, its effect), not an exit code, so a step that passes without doing its job is caught [DEC-1240]. Phase 6 judges the whole run the same way.
6. **Sizes** (audit 4 §2): XS up to 10 lines or a configuration line; S up to 50; M up to 200; L more. **Kinds:** *fix* (a bug or a gap in a closed feature, failing test first), *chore* (records, docs, configuration, retirements, tests unchanged and green), *approved* (a feature or a slice the owner has approved).
7. **Each tool outside the product retires on the day its product tool takes over** (G-5); §2 Phase 4 lists every day.
8. **The tests a landing runs (X-1).** The selection picks them; no one picks them by hand. The whole suite (about 18,000 tests, about 90 minutes) runs only for a release (`gov land --full`, item 3-4) and weekly as the safety net. **A red the selection missed, found by the weekly or the release run, is a selection bug:** it is logged as a new line in `FINDINGS.md`'s form (what happened, evidence, owner, kind `fix`, state) and fixed at its cause, which is a missing edge in the path map or the code and test graph, never a reason for a full run per landing. This replaces DEC-1243 (3) [DEC-1244 X-1].
9. **Pace of the streams (X-5).** Three streams to begin with (L, B, S), F and I joining later (§4); after the capacity assessment (DEC-1234, when W2-207 lands) as many streams as the machine holds, within the load gate (§4).
