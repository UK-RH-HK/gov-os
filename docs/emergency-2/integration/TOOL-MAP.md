**Choices I made (so you can overrule them).**
- *Where it lives:* **P** = in the product: `src/gov/` or the kit `template/` (adopted repositories get it). **O** = outside it: scratch, start scripts, the orchestration folder `governance/project/orchestration/`, a git hook in `.git/hooks`, a cron line, `~/.local/bin`, a user-level setting. A data file a product command reads (`~/.gov-os/machine/gate.json`) is listed under its command, not as a tool.
- *Trigger:* **auto** (by code, and when), **agent** (an agent types it; the CTO counts as an agent), **owner**.
- *On the path:* **Y** = the step really runs through it today; **P** = partly (built and used in part, or only when typed, or only when `gov queue` is used); **N** = bypassed or never used, with the cause.
- *Place:* "0.1.5 in flight" (a branch or a brief exists), "integration" (the plan of DEC-1238 (7); audit 4 called these "0.1.6"), "later" (needs a construction to hit, EMERGENCY-2 §3.2). I read "0.1.5 in flight" from `LEAD-fixes-015a.md`, `e2/d1-verdict`, `e2/d5-memaudit-strict`, `e2/w2-207-runtime` (all unmerged at `5617f2e5e`).
- *Owning ticket:* found with `grep -l "^wbs_id: …" .tickets/*.md`. The file id is in parentheses for the ones I name. "none: new" means no ticket owns it, so it is a feature for the owner's approval (DEC-1238 (7): a new ticket only for an approved feature); a gap in a closed feature is a fix recorded under its owning ticket.
- *Disposition* for every **O** row sits in its last cell as `[absorb]`, `[replace]` or `[retire]`: absorb = move the code into `src/gov` or the kit; replace = the product already has its own tool; retire = delete.
- *Dead and unclear scratch files* are grouped (rows 100 to 106) and counted, not listed one by one, as the brief asked.

**Modules, as the brief asked:** the graph is `src/gov/store/loader.py` plus `src/gov/retrieval/graph_route.py` and `reverse_edges.py` (there is no `src/gov/graph*`); `check/links` is `src/gov/links/check.py` (1,049 lines, integrity of ids and statuses, no spec-to-ticket comparison); `select` is `src/gov/close/select.py`, called by `queue/command.py`; `gov plan` is `src/gov/plan/` (dependencies and paths, not impact); `gov discover` is `src/gov/discover/` (spec → tickets, one direction, at creation).

**Findings that are the CTO's own, checked cheaply:** `gov impact` has no caller in `src/`, `template/`, `.claude/`, `lefthook.yml`, `governance/`, or the scratch tools (the only text is `skills/change/SKILL.md:48-52`); `gov impact DEC-1204` over 106 s and a 150 s timeout is the CTO's measurement and `_Code.__init__` (`:135-150`) is the suspected cause (I read the code; the `codeintel.dead_code(root)` call at `:145` runs for every id, record or symbol, which fits a wait on the code index; I did not re-time).

**The smallest code that would close the gap (four changes, each small):**
1. **`_Code` lazy** (`impact/__init__.py:135-150`): build the code graph only when an id is not a record or a symbol is asked; a record-only id never touches the code index. A fix under W2-37 (DAEO-6n5k, closed); the failing test first: `gov impact DEC-1204` finishes in a bounded time without a code index. About 15 lines.
2. **`gov impact --changed <range>` as the trigger at the landing:** for each record file in the range (a decision entry, a spec, a ticket) run `assess` and print the affected tickets and tests; the queue's after-step (`queue/after.py`) calls it and writes the list into the close record. About 40 lines; a fix under W2-115b/W2-37.
3. **A `KPI_DRIFT` finding in `links/check.py`:** for each ticket with a `spec`/`sources` link to a specification, compare its `[Kn]` KPI lines with the spec's K-lines as `check_spec.py` parses them; report a missing or changed line. About 40 lines; also the brief's ready check (A-23b), a fix under W2-129 (links) and W2-152 (brief).
4. **The back-trace:** invert `accept.runner.parse_map` over `tests/acceptance/*/README.md` into `{test: (ticket, KPI line)}`, and give `gov impact` a test → ticket edge, so a changed test names its ticket and spec. About 30 lines; a fix under W2-96 (accept).

These four make the trace one thing, used by planning (`gov plan`, `gov discover` can read the same affected list) and by the landing, as the draft's "Must be" says; they are a spec question for the owner only on one point, the trigger (SQ-11 in the corrections file).
