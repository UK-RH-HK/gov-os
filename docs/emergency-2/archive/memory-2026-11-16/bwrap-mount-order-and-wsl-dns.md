On 11-16, building the session sandbox (DEC-1198 (3)), my first planted run failed the wall: the planted HOME under /tmp was masked by --tmpfs HOME and then re-exposed by a later --bind /tmp /tmp, so the planted key was read and even moved. Masking all of /mnt also broke DNS, because WSL's /etc/resolv.conf links to /mnt/wsl/resolv.conf. Three more traps: /var/run is a link to /run, so mask the resolved docker socket path; with the host /proc a same-user process reaches /proc/<pid>/root of an outside process, so the PID namespace must be unshared; and the tmux server, the user bus and WSL interop start commands OUTSIDE the sandbox, so all three are masked.

**Why:** a wall that a later mount undoes, or that leaves a door through a host service, is no wall, and only a planted run catches it.

**How to apply:** order the mounts as system, shared /tmp, masks, allowlist, then held-out masks last. Prove the wall in every rehearsal with planted files under a HOME placed inside a shared tree. Related: [[rename-defeats-link-checks]], [[no-rehearsal-against-live]].

**Round 2 (11-16, review NOT READY):** four more holes, all of the same kind: something the session could WRITE was later run, or read, by a process outside. (1) `.git/config` (core.fsmonitor) and `.git/hooks`, which an outside `git status` runs: mount them read-only in every repository. (2) The shared `~/.claude` settings and `~/.claude.json`, which outside sessions run as hooks: give each session its own CLAUDE_CONFIG_DIR, copied in at start. (3) A file-level bind mask is lost when an outside process renames over it: mask the PARENT folder and mount its other children back. (4) The shared /tmp and `~/.claude/projects` leak other sessions' data: use a private /tmp with only the lock files bound in, and mount only the session's own project folder. Rehearse with HOME outside /tmp (e.g. /dev/shm): /tmp hid a parser bug.

**Round 3 (11-16):** a folder that merely CONTAINS mount points can still be renamed aside and replaced (round 2 lost to a moved `.git` and a moved `worktrees/<n>`). Make each protected folder a mount point itself. Anything an outside process runs must come from a pinned read-only copy, never from a tree a box can write (cron ran the dispatcher and nightly from the main tree). A yes must never be read from a transcript the boxed session writes. The live trees had 10 `.git` entries the classifier refuses (stale archive pointers, a pytest leftover): list them before any switch.

**Exception build (11-16 15:4x):** the guard refused my Bash heredoc because it named `.env` (the rule is known: write such edits as a script file with the Write tool, then run the script; I hit it anyway, once, and did not retry the same form). The IDE's MCP ports answer a tokenless WebSocket upgrade (101) but close on a tokenless initialize: that counts as refused, so check the first message, not the handshake. Under DEC-1010 a box finding blocks only if it is reachable in ordinary work AND fails open or loses work; crafted traps are Wave 3 rows.

**Round 2 of the exception (11-16 16:xx):** the narrow check failed on ordinary work, not attacks. A tracked file masked to /dev/null breaks git merge, stash and rebase, so mask only untracked files. Refusing the whole start over one bad folder (an unpinned list, a stray .git) blocks every start as new projects appear, so mask that folder instead. Shared data the tools write (the guard log, gov's machine registry) must be bound in. Five of my probe FAILs were the probes themselves: a no-op `update-ref` to the current value, a reused branch name, a conflict my planted history made, and a probe that corrupted `packed-refs` for every later run. Run destructive probes last, confirm a FAIL outside the box before calling it the box's, and rebuild the world from a script. A variable reused in one function (`own`) silently broke a fix; grep a name before adding it.
