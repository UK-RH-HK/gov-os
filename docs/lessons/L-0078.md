Phase 2's core failure pattern was a review-repair loop. A reviewer would identify a defect in a mechanism. The implementer, working without whole-system architectural context, would build a new local mechanism to address it. The next review would attack the new mechanism, surfacing another defect, which triggered another local repair — and the cycle repeated across multiple rounds.

The pattern was self-reinforcing: each new mechanism introduced new surface area for the reviewer to find issues with, and each repair was scoped to the immediate finding rather than to the system's existing architecture. The result was growing complexity without convergence, when simpler answers — reusing an existing primitive, narrowing the requirement, or deleting the mechanism entirely — were available but never considered because no step consulted the whole system.

DEC-044 recorded the hard loop budget (at most two review-repair rounds per surface before the default disposition becomes DELETE, NARROW, or DEFER), and DEC-046 carried L-0074 and the Phase-2 root-cause lessons forward as principles for the new repository. The anti-snowball rule (OWNER-AMENDMENT-P2-0010 §7) was the direct corrective: requiring whole-system context retrieval and a single architectural disposition before any code change.
