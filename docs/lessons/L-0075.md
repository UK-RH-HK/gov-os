During Phase 2, two unbounded wait incidents occurred. A coordinator-handshake stall ran for 420 minutes, and a self-matching `pgrep -f` wait-loop ran for approximately 10 hours — the process's pattern matched its own command line, so the wait condition could never become false.

These incidents demonstrated that any wait loop without explicit bounds can stall an entire pipeline indefinitely, and that process-name pattern matching can produce self-matches that make the loop logically unfalsifiable.

The lesson learned was that every wait must carry a maximum elapsed time or iteration count, an observable condition that can actually transition, and a deterministic timeout action. Process-group or tracked-PID state is preferred over process-name regex; where pattern matching is unavoidable, the waiter must be proven unable to match itself.

**Source:** OWNER-DECISION-P2-0008 (OD-P2-08) §9, "Anti-stall rule — active for the remainder of Phase 2."
