During Phase 1, a universal negative — "no unauthorised path may be written" — was implemented as a positive enumeration of denied paths. When the product grew new paths that the original author had not listed, writes to those paths were silently permitted. Tests derived from the same enumeration could not detect the gap, because they checked only the paths the list contained.

The root cause was structural: a positive enumeration cannot express a universal negative. As soon as the domain grows beyond the enumerated set, the property quietly stops holding, and any test built from the same list is blind to the new cases.

The lesson carried forward is that universal negatives require default-deny allow-lists, where everything not explicitly permitted is refused, and that checks should derive their scope from the repository's actual state rather than from a hand-maintained list.
