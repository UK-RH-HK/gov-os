**In short.**
- **878 verdicts** on area 3's tests: valid and needed 796, weak 38, duplicate 26, obsolete 8, outdated 6, flaky 4, not reproducible 0. Most of the area's tests are sound. The problems cluster in a few kinds of test:
  - tests that read a frozen record, or pin a file to an old commit;
  - tests whose assertion cannot fail (shown by planted faults);
  - duplicates left beside a revised twin;
  - live and real-model cases that run in the wrong part of the close.
- **W1-42's two accepted reds can never be fixed by the tickets the ratchet names** (finding 1): they read the frozen Wave 1 exit record, which no open ticket may touch. Package R1 proposes retiring them, with their two entries, after the owner's ruling on RETR-X-02.
- **The `load_sensitive` entry** (W1-19's warm p95): flaky. It passes where the close runs it, alone in the serial block of a machine the close holds (eleven closes of eleven on record). It fails on a busy machine: all 7 of my runs, alone in pytest and in its suite's parallel run (p95 1.00 to 5.79 s against 0.5 s), and 26 recorded runs, 25 of them the leads'. Its median query, 0.40 s, leaves under 0.1 s of a line that was set before the question path moved to the CPU (finding 8, package O3).
- **The serial-only block** can shed about 4 minutes per close by moving the live and real-model files to the nightly, as DEC-889 already decides, and W1-16's 94 cases that start no daemon to the parallel part (finding 7). My trial passed those 94 in parallel three times out of three.
- **Four tests pass over a defect that is there today:**
  - W1-24's case for a packet whose index is down passes on an always-true `or`, while the packet is silently empty (finding 16);
  - W1-29's SubagentStop case accepts the reason form Claude Code does not deliver (finding 4);

  - W1-23's synthesis cases pass while the function ignores its budget and raises on real gaps (finding 11).

### Terms used

- **Gov OS, `gov`:** the governance tool this repository builds. A **ticket** is one unit of work (`.tickets/DAEO-xxxx.md`, with a work-breakdown id such as W1-25). Its **acceptance suite** (`tests/acceptance/<id>/`) was written by an independent test designer before the work; its **builder tests** (`tests/unit/`) are the engineer's own.
- **Close (`gov close`):** the command that closes a ticket. It runs the ticket's suite and every other test (the **regression**) in parallel, then the cases of `tests/acceptance/serial-only.txt` alone (the **serial block**). A refused close costs about 80 minutes and a counted attempt.
- **Pre-close gate:** the orchestrator's checks before each close (DEC-868): a rebuild, collection, the record-reading files, a network check and `gov check`.
- **Rehearsal:** the orchestrator's first nightly full run, on a fresh clone of the head `dbd3cc53`, 2026-10-21 17:49 to 19:00 (DEC-888). Its JUnit files give each test's time.
- **`accepted_reds`:** the owner's list of known failing tests that do not refuse a close, each with the ticket that fixes it (DEC-757, DEC-762). **`load_sensitive`:** the owner's list of tests re-run alone when they fail in a close. Both only shrink (DEC-766).
- **Record-reading test:** a test that reads one of this repository's records (`.tickets/`, `docs/checkpoints/`, `docs/close/`, `docs/probes/`, the register, the plan files, `governance/project/orchestration/`; DEC-891), so a record-only commit can turn it red.
- **RESUME HERE:** the section of the orchestrator's or a lead's checkpoint that the session-start hook delivers after a compaction or a resume (DEC-837: in full, never cut).
- **Context packet (`gov context`):** the compiled inputs of a ticket under a token ceiling (CAP-15). **Retrieval (`gov retrieve`):** the search over the lexical index, the semantic vectors and the record graph, in batches (DEC-860).
- **p95:** the 95th percentile of measured times, by the nearest-rank rule: 95 in 100 calls are at least that fast. **hit@5:** the share of a question set whose expected source is among the first five answers.
- **Dev tier:** a synthetic product repository on this machine (`~/gov-os-workbench/synthetic/a-dev` and `b-dev`) that the real-model and code-graph cases index and question.
- **Code graph:** the code index, a wrapper of the tool `codebase-memory-mcp`, which answers callers, definitions and impact; every call starts or reaches a daemon of the tool (W1-16, W1-20).
- **Reranker:** the model that re-scores the merged lexical and semantic hits of a question; it runs in its own Python process, from an environment under the home folder (W1-19).
- **Hooks:** the scripts Claude Code runs at session events: SessionStart (a session starts, resumes or is compacted), PreCompact (before a compaction), Stop and SubagentStop (when a session or a helper ends its turn).
- **Nightly:** the orchestrator's nightly full run on a fresh clone; the rehearsal was its first. **gitleaks:** the secret scanner the indexer runs on each file before indexing it.
- **Shared embedder and CPU embedder:** the Ollama daemon at `127.0.0.1:11434` that builds the vectors on the GPU, and the second one at `127.0.0.1:11435` that embeds questions on the CPU only (DEC-798).
- **DEC-n, CAP-n:** an entry of the decision register, and a capability of the Contract with its covers items (CAP-37.g).
- **Lens:** one review of this assessment. Lens H reviewed the test strategy estate-wide; lens I (this one, split into four areas) reviews the tests themselves; lens B reviewed memory and retrieval.
- **Package:** a question written for a decision, in DEC-818's six parts. P-H-n are lens H's; P-11.2 and the like are packages that test designers wrote into suite READMEs; R1 to R6 and O1 to O4 are this report's.
- **Row:** an item of the Wave 2 list or of Wave 3 (`docs/plan/WAVE_2_LIST.md`), such as W2-M332. **AR-n:** an item of that list's adoption-readiness block (DEC-718); AR-9 holds RETR-X-02's ruling. **DP-n:** a design point that a suite's test designer left in the README for the lead or the owner.
- **CIT-P, CIT-E:** the proposal and the evidence record of a change to the kernel, policy or skills (CAP-33).
- **Lead:** a ticket lead, the session that runs one ticket's loop in its own worktree and verifies it before the close. Its logs are copied to the record branch `record/w2`.
- **`local_only`:** a pytest marker for cases that need this machine (a binary, a model, the dev tiers). The close does not deselect it, so these cases run in every close on this machine.
- **Serial-only list:** `tests/acceptance/serial-only.txt`. Its entries, by kind (latency, real-model-or-daemon, live-session, race), are kept out of the parallel run by the close's plugin and run alone afterwards (DEC-527).
- **xdist, worksteal:** pytest's parallel runner, and its scheduling mode that lets idle workers take queued tests (`-n auto --dist worksteal`). DEC-889 item 11 a adopted it; DEC-892 item a deferred it, so the close, the nightly and the leads run xdist's default distribution until the nested runs are removed. My runs under load used worksteal, as the brief asks. My run in the close's form used the close's own default.
- **W2-57, W2-66, W2-67, W2-68:** the Wave 2 tickets that rework the serial-only list, select the suites a close runs from the changed paths, clean up the tests (per-test copies, nested reruns) and batch closes with run reuse. Their cards are drafted at DEC-889 item 14's review point, which this review feeds.
- **Code fingerprint, record-only path:** DEC-883 item 3 lets a passing run stand for a later head whose code is the same. The fingerprint leaves out the record-only paths, which W2-66 declares ("such as `docs/checkpoints/` and `governance/project/orchestration/`"), in a file of their own since DEC-896 (for example `governance/project/test-map.yaml`). DEC-891's list of what counts as a record (`.tickets/`, the register, the plan files and others) is the natural reading, but W2-66 has not declared its list yet.
- **T-A3:** the one small ticket of test revisions this review proposes for area 3 (section 4.5).
- **`Rewrite-Reason:`:** the line a test designer's commit carries when it changes an existing test, naming why.
- **Planted fault:** a deliberate one-line change in my mutation worktree, to see whether a test can fail for the fault it names. **Weak** means it stayed green.
- **Verdicts:**
  - valid and needed;
  - outdated: a later decision changed the expected behaviour;
  - obsolete: the feature was removed or replaced, or the test only re-reads a frozen record;
  - duplicate: another named test, its twin, asserts at least the same about the same code, so the duplicate adds nothing a fault could show;
  - weak: it cannot fail for the fault it names;
  - flaky: it fails and passes on the same code, with the cause found by running it;
  - not reproducible.
