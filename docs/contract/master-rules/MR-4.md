# MR-4: Audit, discovery and impact are distinct functions

A master rule of the Charter (v6, §4). Generated from `docs/contract/contract.yaml` (Contract v5, version 5.1), which is the authority; this record exists so that the id resolves.

- **Text:** architecture v0.3 §1A (Charter v6 §4)
- **Acceptance:** The functions stay distinct: each of `gov doctor`, discovery, CIT-P, CIT-E and audit has its own command or skill and record. A fresh auditor that authored none of the audited files runs at the release acceptance and at adoption stages A5, AS, A7 and A10; otherwise a review happens only for a red test, a failed landing or merge, or a feature that does not work as intended, batched when several come together; the audit report names its milestone, and contested or owner-level findings appear in chat as decision packages.
