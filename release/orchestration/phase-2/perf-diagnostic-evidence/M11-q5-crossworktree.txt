M11 (Q5): does a build in a different worktree recompile dependencies?
Controlled experiment, no other worktree touched: a second source tree was materialised with
`git archive c34c439` into the scratchpad, and both trees were built with CARGO_TARGET_DIR pointed
at ONE shared directory.

step                                                       wall_s  units compiled  load_before
1. cold build of clone -> fresh shared target               62.08   141             17.34 (contended)
2. build ORIGINAL worktree -> SAME shared target            42.26     2             19.85 (contended)
3. build clone again      -> SAME shared target             38.85     2             19.05 (contended)

Units recompiled in steps 2 and 3 were ONLY gov-runtime and gov-cli. All 139 third-party
dependency units were reused across a different absolute path.

Reference: clean uncontended cold build in the worktree's own target/ = 39.27 s wall, 207 s CPU,
527% CPU, 186 units, 2.1 GB of target/.

Therefore:
 * Dependencies ARE reusable across worktrees; nothing about the tree path prevents it.
 * They are NOT being reused today, because CARGO_TARGET_DIR is unset and there is no
   .cargo/config.toml, so each worktree builds its own target/. MEASURED total: 177,991 MB
   (178 GB) across 41 target directories on a disk that is 79% full.
 * BUT a shared target dir is not a free win: the two workspace crates carry the same
   -C metadata hash in both trees, so they OVERWRITE each other and recompile on every
   cross-tree switch (steps 2 and 3, 2 units each time), and cargo takes an exclusive lock on
   the target dir, which would serialise the concurrent builds this orchestration depends on.
