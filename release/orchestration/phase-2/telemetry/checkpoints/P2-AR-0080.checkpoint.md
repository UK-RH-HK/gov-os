## Update — targeted batch 1 complete, two real regressions found and fixed, plus one small CLI observability fix

`cargo test -p gov-cli --test certification -- r2_failclosed:: repair4:: r4_residual:: remediation_ac:: greenfield::
r2_f3:: p2ho56` (54 passed, 3 failed initially, 1874.98s, default threads) surfaced three failures, all now fixed and
individually re-confirmed green:

1. **Real product regression** (`r4_residual::an_update_moves_the_tracked_os_stores_and_a_rollback_restores_the_previous_layout`):
   `write_project_adoption_floor` unconditionally created `governance/registry/project-adoption-floor.json` even
   with an empty floor, which a bare project (no native layout at all) doesn't need — and `governance/registry/` is
   OS-managed, snapshot/rollback-restored-to-exact-presence-or-absence territory (`update.rs` `SNAPSHOT_DIRS`).
   **Fixed**: `write_project_adoption_floor` is now a no-op when `rules` is empty (`paths.rs`).
2. **Test-authoring bug, not a product bug** (both new `p2ho56_floor.rs` failures): the test process called
   `gov_runtime::t2::verify_file`/`Project::open(...).policies()` **in-process**, but T2's machine-state resolution
   depends on `XDG_STATE_HOME`, which the certification harness sets only on the **subprocess** `gov` env
   (`common.rs`'s `Gov::ok`), never on the outer `cargo test` process itself — so an in-process call resolves a
   different ("FOREIGN") machine view than the one the `gov` subprocess sealed under. Every OTHER T2 assertion in
   this suite already goes through the CLI for exactly this reason; mine didn't. **Fixed**: both assertions now go
   through `doctor_check(&g, "D027")` / `g.ok(&["policy", "effective", ...])` instead of direct library calls.
3. **Small, independently-justified product improvement** (`cli/src/main.rs`): `gov policy effective` only ever
   read `PolicySet.effective` (kernel `policies/*.yaml` only) — a project OVERLAY document
   (`REPOSITORY_CONTRACT.yaml` and the rest of `policy::OVERLAY_FILES`) lived only in `.effective_overlays`, with
   **no CLI surface at all**. Fixed by falling back to `effective_overlays` (by bare name or `.yaml` filename) when
   the kernel-policy lookup misses. This is what let fix #2's tests read the effective overlay through the CLI at
   all, and is a genuine, general observability gap closed, not test-only scaffolding.

All three fixes individually re-confirmed green (`p2ho56_floor::` 4/4 ok in 11.08s; the rollback test ok as part of
a combined run). `cargo build --workspace --tests`: clean throughout.
