# Output 7 — Envelope and statement specification

> **RoT-1 revision 2 — PROPOSED, pending a fresh independent review; not approved, not implemented.**
> Revision 2 introduces purpose-specific payloadTypes, the release stage and promotion, signed trust references, Trust
> Policy, Trust State and verification-attestation statements, compiled-only historical identities, and ASCII-only tree
> paths. It fixes the RV-L1 inconsistencies. Machine-readable schemas: `schemas/`. Worked examples:
> `examples/` (generated by `examples/make_example.py`).

## 1. Layers

```text
<statement>.dsse.json = DSSE envelope (JSON)
  payloadType         = application/vnd.agentic-engineering-os.<type>.<version>+json      (compiled table: 05 §2)
  payload             = base64( GOV-JCS-1 canonical bytes of the statement object )
  signatures[]        = { keyid: "ed25519:<64 hex>", sig: base64( Ed25519( PAE(payloadType, payload_bytes) ) ) }   (≥ 1)

PAE(type, body)       = "DSSEv1" SP LEN(type) SP type SP LEN(body) SP body     (LEN = ASCII decimal byte length)
statement_digest      = "sha256:" + hex( SHA-256( payload_bytes ) )           (signatures excluded → stable across re-signing)
content identity (CI) = ( release statement_digest, kernel.tree_digest )      (18 §1)
```

DSSE is used unchanged, so any conforming implementation can cross-verify. Purpose is bound by the payloadType (PAE) and
cross-checked against payload fields (`05` SV-9).

## 2. Canonical serialisation profile GOV-JCS-1

RFC 8785 with these restrictions, enforced by `05` SV-1/SV-3:

1. UTF-8, no BOM, no insignificant whitespace, no trailing bytes.
2. Object member names are printable ASCII (0x20–0x7E), sorted in byte order. **Duplicate names are an error.** Kernel
   paths used as member names satisfy this because the tree rules restrict paths to ASCII (§5.1).
3. Numbers: integers only, in `[-(2^53−1), 2^53−1]`; no floats, exponents or `-0`.
4. Strings: RFC 8785 escaping; string values must be Unicode NFC.
5. Depth ≤ 32; payload ≤ 4 MiB.
6. The verifier decodes, parses strictly, re-serialises, and requires byte equality.

Value formats:
- digests `sha256:<64 lowercase hex>`;
- versions SemVer 2.0.0;
- timestamps RFC 3339 UTC `YYYY-MM-DDTHH:MM:SSZ` — informational, except TSS `expires_at` under OP-3 mode B (`17` §13);
- commits 40 lowercase hex.

## 5. Kernel tree canonical digest (`gov-tree-v2`)

### 5.1 Tree rules

1. Members are regular files. Symbolic links, reparse points, devices, FIFOs and sockets anywhere in the tree or its
   ancestors → `RELEASE_TREE_INVALID` (ingress) or `PATH_SUBSTITUTION_DETECTED` (use).
2. **Relative path: ASCII only.** `/`-separated segments matching `[A-Za-z0-9._-]+`; no `.`, `..` or empty segment; no
   leading `/`; segment ≤ 255 bytes; path ≤ 1024 bytes. This replaces rev 1's NFC Unicode rule, which conflicted with
   GOV-JCS-1 member names (RV-L1). Every path in the 4.1.2 and 4.1.5 payloads and in `framework/` already satisfies it
   (checked; the longest is 47 bytes).
3. No two paths equal under ASCII case folding (portable to case-insensitive filesystems).
4. Only `KERNEL_MANIFEST.json` at the tree root is excluded.
5. Content digest = SHA-256 of the raw bytes; no line-ending normalisation. The canonical repository sets `-text` in
   `.gitattributes` for `framework/`, `migrations/`, `tools/`, `release/releases/` and `trust/`.
6. File mode is not part of the digest; the installer writes payload files non-executable.
7. Limits: ≤ 10 000 files, ≤ 64 MiB total, ≤ 16 MiB per file.

### 5.2 File map

`files = { relpath: "sha256:<hex>" }`. The tree-digest input is the bare-hex form: `hexmap = { relpath: "<hex>" }`.

### 5.3 Tree digest

`tree_digest = "sha256:" + hex(SHA-256(GOV-JCS-1(hexmap)))`, byte-identical to 4.1.x `release_hash`. This was
independently reproduced for 4.1.2–4.1.5 (`../4.1.6-review/evidence/continuity-check-4.1.2-4.1.5.txt`).

### 5.4 Manifest digest

`manifest_digest = "sha256:" + hex(SHA-256(GOV-JCS-1({framework, version, files: hexmap, payload_hash: <tree hex>})))`,
identical to 4.1.x `kernel::manifest_hash`. It is used only as a digest. The installed `KERNEL_MANIFEST.json` is the
compatibility tombstone (`13` §3), not a manifest.

### 5.5 Component digests

For each component c: `components[c] = "sha256:" + hex(SHA-256(GOV-JCS-1({p: hex | p ∈ hexmap, p starts with c + "/"})))`.
`components["KERNEL.yaml"]` is the file digest.

## 6. Bundle layout

```text
agentic-engineering-os-<version>/
├── release-final.dsse.json             # authoritative (or release-candidate.dsse.json for candidate bundles)
├── lineage/release-candidate.dsse.json # the candidate a final was promoted from
├── kernel/**                           # payload; KERNEL_MANIFEST.json optional and ignored
├── trust/root/<version>.dsse.json      # root links newer than v1
├── trust/policy/<policy_version>.dsse.json
├── trust/state/<sequence>.dsse.json
├── trust/statements/<digest>.dsse.json # attestations, certifications, revocations referenced by the newest TSS
├── artifacts-final.dsse.json           # optional binary digests
├── manifest.json, manifest.yaml        # descriptive only, unsigned, never used for decisions
└── RELEASE_NOTES.md, ROLLBACK.md       # digest-bound via documents
```

Archive form: POSIX tar (ustar/pax), optionally compressed. Members are streamed into buffers. Extraction refuses absolute
paths, `..`, links, devices, duplicate members, non-ASCII paths and anything violating §5.1.

## 7. Producer, signer and publisher interface

| Step | Command / actor | Output | Purpose key |
|---|---|---|---|
| 1 | `gov release build --version V` | payload, descriptive manifests, `release-candidate.statement.json` (unsigned canonical payload). Refuses private key material, `FLOOR_NOT_REGISTERED` and `FLOOR_VIOLATION` against the referenced TPS. Deterministic inputs (`05` §7). | — |
| 2 | external signer on the signing host (reproduces step 1 byte for byte) | `release-candidate.dsse.json` | `release-candidate` |
| 3 | `gov release attach-signature DIR ENVELOPE` | verifies under the compiled root and purpose before placing | — |
| 4 | independent verifier | report, verdict, harness digests | — |
| 5 | external signer (verifier custody) | `verification-attestation.dsse.json` | `verification-attestation` |
| 6 | `gov release promote DIR --attestation A` | `release-final.statement.json`: same content, `stage: final`, next `sequence`, `promoted_from_candidate`. Refuses unless A verifies with verdict ACCEPTED for this candidate digest. | — |
| 7 | external signer (reproduces step 6) | `release-final.dsse.json` | `release-final` |
| 8 | external signer (owner) | `certification-status.dsse.json` (CERTIFIED referencing A, or REJECTED) | `certification-status` |
| 9 | `gov trust draft-policy` (only when floors change) | unsigned TPS generated from the new kernel's constitutional files; diff against the previous TPS, with any lowering listed explicitly | — |
| 10 | root ceremony (only when floors change) | `trust-policy.dsse.json` | `trust-policy` (root threshold) |
| 11 | `gov trust publish --previous <TSS>` | unsigned TSS payload; refuses if not admissible against the previous one (`17` S4) | — |
| 12 | external signer | `trust-state.dsse.json` | `trust-state` |
| 13 | `gov release verify DIR` | V0–V12 in report mode, plus the eligibility, trust-state and certification views | — |

A rejected candidate (verdict REJECTED) is never promoted. Its attestation and, where issued, a revocation are published
in the next TSS.
