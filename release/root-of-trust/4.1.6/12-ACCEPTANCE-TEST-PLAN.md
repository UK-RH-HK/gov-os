# Output 12 — Independent acceptance-test plan

> **RoT-1 revision 3 — PROPOSED, pending a fresh independent review; not approved, not implemented.**
> This plan says **what** the independent verifier of 4.1.6 must prove; the verifier authors its harness independently.
> Revision 3 makes these changes (R2-M10):
> - keeps RT-01…RT-72 with revised expectations;
> - adds RT-73…RT-100;
> - maps every review r2 held-out attack RV2-A01…A36 to an expected code;
> - gives pass/fail criteria to the former documented-residual variants;
> - replaces self-referential expectations with property assertions;
> - moves [FS] evidence to OS-level tracing run by the verifier.

## 1. Rules for every scenario

1. Black-box through `gov --json`; fresh consumer repositories; no builder helper code.
2. **Declared trust base.** Every scenario states the binary's TBM: compiled root version, TPS version and digest, TSS
   sequence. It also states the VTS state: anchor epoch and method, or none; OP-7 mode.
3. **No-trusted-write assertion.** Hash the whole working tree (excluding `.git/` and `.governance-runtime/`) and the Git
   state before and after every refused operation. They must be identical, except a declared refusal ledger entry.
4. **Harm assertions.** Wherever an attack weakens constitutional content, run all of these:
   - (a) restricted material inside the index scope stays excluded and not retrievable;
   - (b) an L1 role performing an L4 operation is `AUTHORITY_DENIED`;
   - (c) an agent answering an R5 irreversible gate is `AUTHORITY_DENIED`;
   - (d) the specific leaf's consumer shows the genuine or registered behaviour.

   These apply to floored and formerly unfloored inputs alike (review r2 `07` §2).
5. **Typed refusal.** `ok: false`, the exact `error.code`, and `details.stage` or `reason`.
6. **Never-current assertion.** After any attack, `gov kernel trust` must not report `verified: true`, `ELIGIBLE`, a better
   certification view, or a `freshness` better than the attacked state warrants. `CURRENT_KNOWN` must never appear.
7. **[FS] scenarios.** The **verifier** traces every file and process system call with OS tooling (`strace -f -e
   trace=%file,%process`, fanotify or eBPF). It asserts no Protected Path or occupation-entry mutation outside `install_tx`,
   and no open of `governance/trust/**` outside `kernel_trust` and `install_tx`. Instrumentation compiled into the product
   is not evidence.
8. **[RACE] scenarios.** At least 20 trials; a single success fails the scenario.
9. **Key material** for attacks is generated by the verifier, and a second independent Ed25519 and RFC 8785 implementation
   cross-checks.
10. **Profiles.** `gov` with the owner-signed 4.1.6 set; `gov-test-profile` with verifier-signed test lineages covering all
    eleven purposes.
11. **Property assertions, not copied expectations.** No expected result may be defined as "as the architect's evidence".
    The architect's P1r3, P3r3, P4r3 and the CSI self-test are reproduction targets. The verifier derives its own
    expectations from the properties below.
12. **OP-7.** Scenarios run under the owner's OP-7 answer. Scenarios marked **[OP7]** run under every option (a)–(d).
