# Output 12 — Independent acceptance-test plan

> **RoT-1 revision 2 — PROPOSED, pending a fresh independent review; not approved, not implemented.**
> This plan specifies **what** the independent verifier of 4.1.6 must prove. The verifier authors its harness
> independently of the builder. Revision 2 keeps RT-01…RT-30 (revised), adds RT-31…RT-72, and maps every case the owner
> required (§4) and every held-out attack of the independent review (§5).

## 1. Rules for every scenario

1. Black-box through `gov --json` only; fresh consumer repositories; no builder helper code.
2. **No-trusted-write assertion.** Hash `governance/` (including `trust/`, `.tx/`, `framework.lock`) and `spec/` before and
   after each refused operation. They must be byte-identical, except a refusal ledger entry if the implementation writes
   one (declared in the report).
3. **Harm assertion** wherever a tamper removes or lowers a floor. Use restricted material **inside the index scope**
   (e.g. `spec/decisions/*.yaml`, `product/*.md`, as established by the review's R2b scope check). It must stay excluded
   and not retrievable.
4. **Typed refusal.** `ok: false`, the exact `error.code`, and `error.details.stage` or `reason` as specified in `09` §4.
5. **Never-verified assertion.** After any attack, `gov kernel trust` must not report `verified: true`, `ELIGIBLE` or a
   certification view better than the attacked state warrants. Doctor D030–D034 must show the specified severity.
6. **Filesystem interception.** Scenarios marked **[FS]** run with the test-build interception layer. They assert no
   Protected Path mutation outside `install_tx` and no open of kernel or trust paths outside `kernel_trust`/`install_tx`.
7. **Races.** Scenarios marked **[RACE]** run at least 20 trials; a single success of the attack fails the scenario.
8. **Key material** for attacks (unknown keys, wrong-purpose keys) is generated by the verifier. A second independent
   Ed25519 and RFC 8785 implementation cross-checks PAE bytes, signatures and canonical payloads.
9. **Profiles.**
   - The production binary `gov` runs with the owner-signed 4.1.6 candidate/final set for production semantics.
   - `gov-test-profile` runs with verifier-signed test lineages covering all nine purposes for the matrix.
   - Each scenario states which.
10. **OP-3 modes.** Unless stated, scenarios run under the TPS gating mode chosen by the owner. Scenarios that involve
    mode B also run on a test TPS with mode B.
