# 02 — Held-out attack register (RV4-C-A01 … A10)

Authored by this review; none is in the pack acceptance plan (`12`). **E** = executed with the real binaries / real Git;
**D** = design-level (the RoT-1 install/transaction machinery is architecture-only, so it is reasoned from `18`/`20`/
`26`/`27`). Acceptance criterion per attack: does an ordinary or legacy operation produce a state that is silently
mutated under `governance/trust/**`, a state a RoT-1 binary later treats as valid, or a persistent silent loss of a
control? **Pass** = the design/binaries resist; **Gap** = a residual worth a finding or carried requirement.

| ID | Attack | Kind | Result | Verdict |
|---|---|---|---|---|
| **RV4-C-A01** | **Subdirectory escape.** Run `init`, `adopt baseline`, `migrate baseline` (which root at `current_dir()`) from each of nine subdirectories of an intact revision-4 project with **no** `--root`; whole-tree + `governance/trust` before/after; `18` §9 state after. | E | Nested legacy install created in every subdirectory (336 invocations). From `governance/trust` and `governance/trust/state`, **56** invocations write **inside `governance/trust/**`**; the outer RoT-1 state stays **`COMPLETE`** with occupation intact. Rooted (`--root`) control: 2,504 rows, 0 writes. | **Gap → RV4-C-H1 (HIGH)** |
| **RV4-C-A02** | **Retained-gitignore untracking idiom.** Migrate a project whose `.gitignore` keeps the legacy `.governance-runtime/` line (append), then `git ls-files -ci --exclude-standard` → `git rm --cached` → commit → fresh clone. | E | The idiom lists `.governance-runtime/migration`; the fresh clone is `PARTIAL(occupation)`. The replace-form tree lists nothing (`COMPLETE`). RV3-L7 reopens for retained-line projects. | **Gap → RV4-C-M1 (MEDIUM, carried)** |
| **RV4-C-A03** | **Symlink substitution of an occupation entry.** Replace the `governance/framework.lock` occupation directory with a symlink to a real directory; check the `18` §9 type test and the legacy binary. | E | `18` §9 model flags the entry as type `link` ≠ `dir` → `PARTIAL`; the legacy binary is `NOT_INSTALLED` (kernel manifest absent) and writes nothing. Confirms C-4 (`st_mode`, not name). | Pass (bounded) |
| **RV4-C-A04** | **Nested legacy project as a subtree.** Install a legacy 4.1.x project in `vendor/legacypkg/` of the RoT-1 project; run a destructive legacy command from deeper inside it with no `--root`. | E | Root discovery finds the nearest `governance/framework.lock` (the nested one); all writes stay within `vendor/legacypkg/`. Outer RoT-1 = `COMPLETE`, `governance/trust` untouched. Contained (this is the *same-root* case of A01, contained because the nested root is outside the RoT-1 tree). | Pass |
| **RV4-C-A05** | **Sparse checkout.** Cone-mode `sparse-checkout set governance`, and non-cone omitting the occupation while keeping `governance/trust`; then legacy `init --force`. | E | Both leave root occupation entries absent (`.governance-runtime/migration`, `spec/audits/GOVERNANCE-ADOPTION` under cone; `governance/kernel` under non-cone) → `PARTIAL`. Legacy `init --force` fails `IO_ERROR` at the `framework.lock` directory, `KERNEL_TAMPERED`, no restricted retrieval. | Pass (bounded; the occupation spans three tree roots — see `03`) |
| **RV4-C-A06** | **Occupation removal / Git restore + legacy CIT (LR-2 / RV3-M6 re-run on the revision-4 layout).** Full occupation removal + `init --force`; `git checkout <pre> -- governance`; `git restore --source <pre> -- governance`; then a legacy CIT whose manifest writes `governance/trust/kernel/policies/SECURITY_POLICY.yaml` and deletes `governance/trust/framework.lock`. Control: intact layout. | E | Removal/checkout: legacy `verified: true`, post-migration-classified `product/customers/acme.md` retrievable, legacy CIT **mutates `governance/trust`**; RoT-1 = `PARTIAL(occupation)`. Restore: RoT-1 = `LEGACY`. Control intact: every legacy step `NOT_INSTALLED`, `governance/trust` unmutated, RoT-1 `COMPLETE`. Matches `26` §8 LR-2 exactly; RoT-1 fails closed everywhere. | Pass (documented residual; bound holds) |
| **RV4-C-A07** | **Delivery / mutation durability.** Fresh clone, shallow clone, `git archive`, `git clean -fdx`, stash/pop of a dirtied occupation, `git worktree add`, checkout across the migration commit and back, `git revert`. | E | Occupation and types reach every clone/tarball; `clean -fdx` keeps the tracked occupation; stash/pop preserves types; checkout back restores types (`COMPLETE`); revert is a clean full downgrade (`LEGACY`, no RoT-1 state). `worktree add` on a bare-less repo returned rc≠0 in the harness (worktree of a non-bare clone), not a durability loss. | Pass |
| **RV4-C-A08** | **Foreign / crafted transaction journal.** (design) A committed or copied `.governance-runtime/trust-tx/<TX>/journal.json`, or one registered in another project's VTS, presented to `gov recover`. | D | `18` §5.1 / `20` §5: a journal is honoured only if the VTS per-project record lists `<TX>` open for this `project_trust_id` **and** the path is untracked, else `FOREIGN_TRANSACTION_ARTEFACT`. Sound as specified; unimplemented, so spec-only. Note: my A01 shows a legacy binary can write `governance/trust/.governance-runtime/**`, but not the root `.governance-runtime/trust-tx/`. | Pass (spec only) → `04` |
| **RV4-C-A09** | **Cross-device / rename-exchange transaction area.** (design) `.governance-runtime/trust-tx` on a different `st_dev` from `governance/` (Docker overlayfs, tmpfs runtime dir, bind mount). | D | `18` §3: `TRUST_PLATFORM_UNSUPPORTED(cross_device_tx)` before any write; a `PARTIAL` remains repairable by same-digest `kernel reinstall`. Sound as specified; unimplemented. | Pass (spec only) → `04` C-2 |
| **RV4-C-A10** | **Concurrent / long-lived / crash.** (design) Two `gov` processes; a long-lived MCP loop across an update/revocation/anchor change; crash at each transaction phase. | D | `18` §5.3/§5.4, VU-11: exclusive tx lock, shared-lock generation check with `snapshot_max_age`, journal phases with union `state/`. Sound as specified; the MCP server “MUST adopt VU-11 before it ships” is a forward obligation. Unimplemented. | Pass (spec only) → `04` |

## Summary

- Authored **10** (RV4-C-A01…A10). Executed **7** (A01–A07); design-level **3** (A08–A10, transaction machinery
  unimplemented).
- **1 blocking gap** (RV4-C-A01 → RV4-C-H1) and **1 carried gap** (RV4-C-A02 → RV4-C-M1).
- On the intact revision-4 layout, **no `--root` invocation** mutated `governance/trust/**` or produced a state a RoT-1
  binary treats as valid; the only writes came from `init`/`adopt baseline`/`migrate baseline` invoked **without**
  `--root` from a subdirectory (A01), and from occupation removal / Git restore (A06, the documented LR-2 residual, which
  RoT-1 fails closed on).
