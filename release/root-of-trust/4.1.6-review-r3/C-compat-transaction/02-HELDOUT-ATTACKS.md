# 02 — Held-out attack register (RV3-C-A01 … A10)

Authored by this review; not in the pack acceptance plan (`12`). **E** = executed with the real binaries. **D** =
design-level (the RoT-1 install/transaction machinery is architecture-only, so it is reasoned from `18`/`20`/`26`,
not executed). Acceptance criterion for each: does an ordinary or legacy operation produce a state that is silently
mutated in `governance/trust/**`, or a state a RoT-1 binary later treats as valid, or a persistent silent loss of a
control? "Pass" = the design/binaries resist; "Gap" = a residual worth a finding or carried requirement.

## Summary
- Authored: **10** (RV3-C-A01…A10). Executed: **6** (A01–A06, A09; A07 partly). Design-level: A08, A10 (+A07 type reasoning).
- One residual gap surfaced across A04/A05/A06 → finding **C-1** (MEDIUM, carriable).
- No attack mutated `governance/trust/**` with a pre-RoT binary, and none produced a state a **RoT-1** binary treats
  as valid: RoT-1 fails closed (`PARTIAL(occupation)` / `LEGACY`) in every occupation-broken case.
