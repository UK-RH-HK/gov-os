# 04 — Carried requirements (bound, testable; not blocking)

Each item is fail-closed, inert, fail-safe, or a specification ambiguity that a bound rule removes; none changes a trust
relationship, so each can be carried into implementation and independent OS verification without an architecture revision.
Where a finding has an unsafe reading, the requirement below is the rule that removes it; an implementation that follows the
unsafe reading does not meet the requirement.
