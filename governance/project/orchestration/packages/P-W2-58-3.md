# P-W2-58-3 — A search from above a secret-named file prints the secret

Blocks: nothing of W2-58's current round. It decides whether one more guard rule rides along in a later iteration, or becomes a row. P2.

1. **Context.** DEC-820 (a): "a key, token or secret is never printed". W2-58 refuses every content read that names a secret by its name (`.env`, `.env.*`, `*.pem`, `*.key`, `config/secrets*`, `~/.ssh/**`, the CLI's credentials file; this round adds `*.env` and `.secrets/**`, the names this repository's `.gitignore` keeps for provider credentials). The run-1 lead's brief chose not to refuse a search that starts at a folder above such a file, so that the searches from the repository root DEC-857 opens stay open. The index already keeps secrets out (W1-15's filter).

2. **What happened.** The review of 2026-10-21 (head `8caf47db`) ran `grep -rn <word> .` from a fixture root as product-spec, orchestrator and auditor: it printed all eight stand-in secrets. `find . -name '.env*' -exec cat {} +` is refused (it names them). The base had no secret rule at all, so this is not a regression.

3. **Why it matters.** Wherever such a file exists in a working tree, the commonest search there is, a grep from the root for a word that occurs in it (`API_KEY`, a provider name), prints the key into the session's transcript. Ordinary work: yes, where such a file lies under the searched folder (whether one exists now in any tree was not checked: the reviewer's listing was refused, and the lead did not look). Consequence: fails open.

4. **Options.**
   - **(a) Refuse an unnarrowed search from above a secret-named file that exists,** as (c) and (d) do (a path or glob that keeps it out lets the search through). Consequence: in a tree that holds such a file at any depth, every unnarrowed root search is refused again, for every role, auditors included: DEC-849's refusals come back in exactly the trees that keep credentials, and the refusal message must name no path. Cost: one engineer iteration (the machinery exists for (c)/(d)), a test batch, a review: about 3 hours. Risk: medium (it re-closes reads DEC-857 opened).
   - **(b) Row it for Wave 3** (W2-L list), with the index's filter and `.gitignore` as today's controls, and a note in the bootstrap that credentials are kept outside working trees. Cost: none now. Risk: a secret printed into a transcript in a tree that keeps one.
   - **(c) Move the credentials out of the working trees** (the owner's own act, e.g. under `~/.config/`), and keep (b)'s row. Cost: minutes, the owner's. Risk: low.

5. **Recommendation:** (c) with (b)'s row. Confidence: medium. Classification: Ordinary work: yes, because a root grep is the commonest search, where such a file exists. Consequence: fails open. Option (a) trades it against DEC-857 in exactly the trees that hold credentials.

6. **What it blocks, and what waiting costs.** It blocks nothing in W2-58's round. Waiting leaves the gap as on the base.
