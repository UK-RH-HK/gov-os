# P1-W2-88-RV2-1: W2-88's last review round fails on one blocker (A9's undo resets the tree)

**(1) Context.** W2-88 (`DAEO-2bdu`) is on EXAMIN's critical path: adoption's assessment, the fabric stage A9 and its
proofs. Review round 1 failed with 11 findings (P-W2-88-B-1, decided 05:35), and run 4 fixed them. Round 2 is the last
review round (DEC-1010: at most two; if something still blocks, it goes to the owner once, with options). The record is
`docs/probes/DAEO-2bdu/PR-DAEO-2bdu-round-2.md` on `w2/W2-88` (commit a15de913e), probed at `15ad055adbb5`.

**(2) What happened.** All 11 of round 1's findings are fixed. One new blocker comes from run 4's own fix for B-1.1 (the
kernel skills copied in at adoption):
- **RV2-1.** If A9 refuses or is interrupted after it has copied the kernel files, it undoes them with W2-23's
  `project.restore`, which is `git reset --hard <the commit A9 started on>` (`fabric.py:218-226`, `project.py:110-125`).
  That happens on any exception after the copy step (`fabric.py:564-569`): `FABRIC_INCOMPLETE`, `REBUILD_FAILED`,
  `DIGESTS_INCOMPLETE` or Ctrl-C. That window is the whole rebuild and measure, more than an hour on a large
  repository. The reviewer reproduced two losses:
  - an edit to a tracked file made during the run is gone;
  - a commit made during the run is dropped from the branch, and survives only in the reflog.
  No procedure text tells the operator to keep the repository untouched while a stage runs.
  Classification: in scope, ordinary work yes, consequence loses work.
- **RV2-2** (minor): in `PLAN.md`, the first unscanned path sits on its heading's line. It is one line, fixed alongside.

**(3) Why it matters.** Adoption runs on EXAMIN's copy (W2-27), then on the real repository. A long A9 interrupted by
Ctrl-C, or run while someone edits in another terminal, silently throws away their work. That is the "loses work"
the threat model guards against in ordinary work (ADR-0001).

**(4) The options.**
- **(a) Fix it in this ticket** (the lead's recommendation; `fabric.py` only, W2-23's `project.restore` unchanged). On
  a refusal or interrupt, A9 does three things:
  - it unstages only the paths it staged;
  - it deletes only the files it wrote whose bytes are still the ones it wrote, plus the empty folders it made;
  - if HEAD moved during the run, it refuses without resetting, names the new commit and leaves the branch alone.

  RV2-2 is fixed with it. Then a narrow independent check of that change (DEC-1154's practice, no third review round),
  and the land. Cost: about 2 to 3 hours (a fix run, the two cases the reviewer gave, the narrow check). Risk: low,
  and it is contained in one file. Nothing changes in the Contract, specs or skills.
- **(b) A rule instead of code:** the adopt skill and A9's own output say the repository must not be edited or
  committed while a stage runs. Cost: the skill is kernel bytes (a CIT-P for your approval and a copies ACT), about
  the same time as (a) in all. Risk: Ctrl-C still resets whatever the operator did meanwhile; a rule does not stop the
  loss.
- **(c) Rule that concurrent work during adoption is not ordinary work** (a Wave 3 row) and land as it is. Cost: none
  now. Risk: the loss stays in the product that EXAMIN's copy and repository will use.

**(5) Recommendation: (a)**, confidence high. It removes the loss at its cause, inside the ticket's own paths, and
costs a few hours on the critical path. The reviewer's description of the correct behaviour is ready for the cases.

**(6) What it blocks.** W2-88's land, and with it W2-174 and W2-27, the critical path to EXAMIN's copy (about 11-20).
Each hour of waiting is an hour on that date. The lead's other work is done.
