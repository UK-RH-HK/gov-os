# P-W2-90-1: two gaps in the kernel's template, found by W2-90 (P1-A installs, P1-B a hook line without a pin)

For the owner. W2-90 moved 228 of the 235 live-wiring cases to the kernel's template and a project generated from it; they pass on both heads, and W2-90 is merged (`21eac66b`, DEC-965). Seven cases cannot move without lowering an expectation, because the template itself does not do what they assert. Both causes touch installs or a fail-open, so they are yours (DEC-957's rubric).

## 1. Context
- **Before ACT 1,** these cases tested this repository's own live wiring. After it, they test what an adopted product gets: the template's generated settings and hooks.
- **The checks:** W1-04, W1-46 success 6 and DEC-172 say an install is decided by the guard's install rule. That rule asks the CTO's session and refuses the others; nothing denies an install before the hook runs. DEC-822 gave this repository's hook lines a pinned interpreter, so a session's `PYTHONPATH` cannot change which guard code runs.

## 2. What happened (checked in the files, 2026-10-31 01:20)
- **P1-A:** `template/.rulesync/permissions.jsonc` lines 7 and 8 deny `npm install*` and `pip install*`. In a generated product Claude Code refuses these before the guard is asked, so the CTO's session can never be asked. This repository removed the same rules by DEC-172. It blocks 3 cases: W1-05's two "the orchestrator is asked" cases and W1-46's research `npm install` case.
- **P1-B:** `template/governance/kernel/settings.json` (lines 8, 20 and 32) runs each hook as `python3 "$h"`, with no pinned interpreter. W2-90's test designer measured it: in a session whose `PYTHONPATH` points at an edited copy of `gov`, the hook imports that copy and lets a refused write through (exit 0). This repository's lines carry the pin (DEC-822, W2-59). It blocks 4 W2-59 cases.

## 3. Why it matters
- Both gaps reach every repository the Gov OS adopts, EXAMIN's copy first.
- **P1-A** breaks the owner-approves-installs flow in a product: the request never reaches you.
- **P1-B** lets the guard's code be swapped by an environment variable. Classification:
  - **Ordinary work:** unlikely but possible, because it needs a session started with `PYTHONPATH` set (leads set it per command, not for the session).
  - **Consequence:** fails open.

## 4. Options
**P1-A**
- **(a) Recommended:** a small product-spec ticket removes the two deny rules from the template, as DEC-172 did here; a test designer then moves the 3 cases. About 2 hours, plus a re-run of W1-38 and W1-39 (the template's own suites).
- **(b)** Re-baseline those three KPI lines for products, which changes the spec.
- **(c)** Defer, with 3 named known reds until then.

**P1-B**
- **(a) Recommended:** a ticket gives the template's hook lines W2-59's pinned form, resolved at adoption from the installed release (W2-16's frozen release); the 4 cases then move. About 4 to 6 hours.
- **(b)** A Wave 3 hardening row, reading the start of a session with a hand-set `PYTHONPATH` as a deliberate construction (DEC-801). This keeps 4 known reds through EXAMIN's copy.
- **(c)** Re-baseline W2-59 for products.

None of these changes the Contract. Option (a) for each adds a small ticket to Wave 2's minimum.

## 5. Recommendation
- **P1-A (a),** confidence medium-high.
- **P1-B (a),** confidence medium. The pin is cheap, and EXAMIN's copy is the first product to run these lines.

Classification: P1-A, ordinary work yes, other (breaks the install flow). P1-B, ordinary work rarely, fails open.

## 6. What it blocks, and what waiting costs
- **Blocks:** only these 7 cases, and W2-90's next round, which also moves the 14 ids ACT 1 dropped (DEC-965).
- **Waiting costs:** 7 named known reds in the nightly and in full closes, and both gaps would ship in EXAMIN's copy.
