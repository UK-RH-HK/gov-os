# P-W2-48-5 (with P-B) — The test cache, built safely, reuses only 16 % of the tests here: how far may it go to save the hour? (P1; gates W2-48's purpose)

**From:** W2-48's lead (run 1, `log/W2-48-A5-run1.json`), brought by the W2 orchestrator, 2026-10-20 17:45 BST.

## 1. Context
The owner put W2-48 first after W2-53's close (DEC-869) because "until it lands, every close costs over an hour". DEC-843 glues the cache to pytest-testmon and coverage; DEC-852 item 1 says the cache must see the code a test runs in a separate process, or always re-run any test that starts one: **a test whose code changed never gets a reused result.**

## 2. What happened
- The cache is built and correct under those rules: 32 of its 46 acceptance cases pass; the rest wait on the close's wiring (decided, DEC-875), one fixture defect (decided) and the time-saved figure.
- **Measured on W1-01 to W1-15:** 4,858 of 5,731 tests (83 %) always run; 16 % were reused, mostly fast unit tests. The two largest causes:
  - tests start a child with an environment built from scratch, so coverage's subprocess hook does not reach it;
  - `gov` itself calls `git`, a non-Python program the cache cannot see into.
  - Tests that read a non-Python file nobody declared always run too: this repository's path map declares no `test_inputs`.
- So, as built, the close's hour stays about an hour.

## 3. Why it matters
DEC-869's purpose: every later close (about 50 left in Wave 2) costs about an hour, plus the nightly full run.

Classification: no reviewer finding. The trade-off is fail-open risk (a stale reuse) against time.

## 4. Options
- **(a) Keep the safe rules; accept a small saving.** No new risk; the closes stay about an hour.
- **(b) Measure more children,** within "never reuse unseen code": give children started with their own environment the coverage variables and site path, and treat known non-Python programs such as `git` as part of the environment, keyed by their version. One engineer round, about 150 to 250 lines. Fail-open risk where a child escapes measurement; covered by acceptance cases, the FULL review, and the nightly full uncached run (DEC-852 item 3), where a test that fails uncached but passed through the cache is a P1.
- **(c) You declare narrow `test_inputs` for this repository** in the path map (P-B: fixtures, templates and schemas; the register and the ticket files left out), so that tests reading those files are keyed on them instead of always running. One edit, by your decision (the orchestrator commits it, DEC-861).
- **(d) Defer the saving.** W2-38 (impact-selected tests) is now in Wave 3 (DEC-841), so this means no saving in Wave 2.

## 5. Recommendation
**(b) with (c), confidence medium.** The nightly uncached run is the backstop for (b)'s risk. If the owner prefers no new fail-open surface, (c) alone is safe (an undeclared read still makes a test always run) but saves less.

## 6. What it blocks, and what waiting costs
W2-48's next round, which is to carry the wiring, the cache-only reds (W1-07's copied-repository setup race; latency cases slowed by coverage), the lead's-run failure output and the timed figure. Without (b) or (c), W2-48 merges, but every close stays about an hour.
