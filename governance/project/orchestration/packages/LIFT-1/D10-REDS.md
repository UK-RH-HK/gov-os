## 2. Whether each feature returns, and when

- **G-4 (write scope by ticket) and G-5 (post-command containment)** return with the product's full guard. That is
  after the resume, when this repository runs the kernel's guard again. DEC-1061 (3a) says G-4 to G-6 then **bring their
  own scoped tests**. The W1-33 case turns green as it stands when G-4 returns. The W1-05 case's fixture passes when a
  PostToolUse hook for Bash is registered again.
- **But the two "not moved to the kernel" rows may never return in their present form.** The kernel's settings,
  generated by rulesync from `template/.rulesync/permissions.jsonc`, deny `Bash(pip install*)` and `Bash(npm install*)`
  before any hook runs. W2-90 recorded this when it moved the other forms. Consequences:
  - In a product, W1-05's pip and npm rows would be denied, not asked.
  - W1-46's npm row would be denied, not let through.
  - Both rows still pass only against this repository's own pre-switch settings.
  - This is a contradiction between the product's template and W1-04's KPI and CAP-25.e for those forms. It is not a
    test fault. It belongs to W1-46's and W1-05's home tickets when D-10's lifted run files its reds (DEC-1061 (2)),
    with DEC-105's three options: allow the research role's npm and pip installs in the template; narrow the KPI to
    the forms the template allows; or defer to the resume.

## 3. What a rewrite for today's hook would cost, case by case

- **W1-33, a split** (the only rewrite that keeps the case's own purpose):
  - The two green checks become one gated case: "the auditor writes its report path and nothing else" (rule 5).
  - The engineer's-ticket check becomes its own case, still lifted, named for G-4.
  - Cost: one designer pass (about 20 minutes), one narrow review, and one line edit in
    `tests/optin-lifted-guard.txt` (an operator ACT, as ACT-D4-RESTORE-1's were; a tightening, class (a)).
  - **Gain: none in protection.** Rule 5 is already gated in `test_live_hook.py`. The gain is bookkeeping only: W1-33's
    KPI 2 keeps a gated case in its own suite.
- **W1-05, a rewrite to today's rule 4:**
  - A new fixture that needs only the PreToolUse wiring.
  - The ask made as the CTO (the orchestrator on the coordination ticket, which the committed copy must carry).
  - The three permission modes kept.
  - Cost: one designer pass (about 30-45 minutes) plus the review and list edit as above. The case would then hang on
    this repository's coordination ticket id.
  - **Gain: little.** It would duplicate `test_live_hook.py`'s CTO row. The modes add nothing while the settings hold
    no install rule.
- **W1-46, a rewrite to today's hook:**
  - This would turn "let through" into "refused". That changes W1-46's KPI 6 (CAP-25.e), not its test.
  - So it is a Contract change, for the owner (CAP-33), not a test revision.
  - **Not recommended as a rewrite.**
  - Today's refusal of a research install can be gated cheaply instead: one research row in
    `test_live_hook.py`'s RULE_4. Cost: an engineer, about 10 minutes, one review. This leaves the acceptance case
    untouched.
