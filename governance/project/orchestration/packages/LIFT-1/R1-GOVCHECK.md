# R1: do the merge queue and the close already run what `gov check` protects? (DEC-1050 (1)-(4))

**Headline.**
1. **No `gov check` runs in the merge queue (`merge_queue.py`), in `land.py` or in `close_build.py`.** Only the product's strict `gov close` runs it, and nothing here has used that since 28 Oct (Q-2). The nightly never runs `gov check` itself. Its only run is the hidden one inside W2-54's tests, and that test checks only core-schema and context-reproducibility.
2. What the queue does run on the merged code is a set of tests. W2-54's hidden full `gov check` (382 to 1,484 s, but only core-schema is checked). And the `record_reading` "here" cases, which take seconds: core-schema (W2-02), path map (W1-08), graph and register (W1-10), probe records (W1-26). These cover the schema, path-map and graph families. **E2's T-4 change (`emg/select` 83b7f85f) takes all of them out of every selection that goes through `select_tests.py`**, because that tool strips record-only paths before `select.plan` sees them. So the new "a record path changed" trigger never fires.
3. The inputs of most families are records: tickets, the register, the path map, `.claude/`. The CTO commits these **straight onto `w2/integrate`, never through the queue**. Since 25 Oct: 270 commits to `.tickets/`, 124 to the register, 7 to the path map, 8 to `.claude/`. Leads' `gov check` was the only frequent thing that saw them. Its one real catch in aim is `core-mutation`: an engineer ticket's `allowed_paths` covering `tests/acceptance/` (DAEO-tgk2, then DAEO-a3u2). At least 10 lead returns reported it, nobody acted, and it is **still red on `w2/integrate`**.
4. **Conclusion:** leads' `gov check` can go altogether, as `cc8f64c9` already did. No family needs a run in the lead's worktree before the merge: the checks' own code is tested by `tests/unit/check` (in every selection) and by the W1-26 coupling. **But the brief's reason is wrong.** With E2 in and the nightly stopped, nothing would run the structural families on merged code. Nothing would run them on the CTO's direct commits either.
5. **The fix is small and costs under a minute (estimate):** run six structural check modules, which are stand-alone commands, on the merged result in `land.py`, after a queue run lands. Run the same six after the CTO's own record commits. Everything heavy stays out until the refactored nightly.
