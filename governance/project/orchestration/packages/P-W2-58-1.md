# P-W2-58-1 — The sandbox clause of Policy 2 (c) and (d) cannot hold together with running the tests or the scorer inside the session

Blocks: part of W2-58 (one engineer iteration on the launcher's sandbox rules, then the review and DONE). The guard part is built and verified. P1 for W2-58: W2-58 gates every start after it (DEC-857).

1. **Context.** DEC-821 items 1 and 2, and W2-58's KPIs 1 to 3, ask for each of (c) and (d) to be refused "by the guard ... and by its sandbox". In the same KPIs, the session must still work with what it is refused:
   - KPI 1: the engineer "can still run those tests with pytest";
   - KPI 2: the test designer's tests import the branch's code;
   - KPI 3: "the measurement script scores it" from the measured session.
   The lead's brief read "by its sandbox" as a `Read` deny rule in the launcher's settings. Such a rule binds the file tools but not the operating system's reads by the session's commands. The launcher's own description says the Linux sandbox skips a rule with a wildcard (`src/gov/launch/launcher.py`, `_runtime_rules`).

2. **What happened (measured, 2026-10-20).** The CLI resolves every `Read` deny rule that matches existing files into a literal path in the commands' sandbox (`filesystem.read.denyOnly`). Three rule forms were tried:
   - `<folder>/**`: the engineer's relaunched session; `pytest --co` collected nothing.
   - `<file>*`: the test designer's resumed session. It got `ModuleNotFoundError: No module named 'gov.guard.decide'` and could not import the branch's code.
   - `tests/acceptance/W2-5[8]/**` (the current head): a live engineer probe on `46713d8b` (log `probe-eng-1.json`). `pytest tests/acceptance/W2-58 --co` reported "no tests collected". `git status` showed all 12 tracked test files as ` D` (deleted), and `git update-index --refresh` exited 1.

   Running a file means reading it. No rule form can be relied on to deny the Read tool while leaving the commands free to read the same files.

3. **Why it matters.** Merged as it stands, the launcher breaks the loop for every ticket:
   - Every launched engineer would be unable to run its own acceptance tests.
   - Every test designer's rewrite round would be unable to import the code it tests.
   - Every measured session would be unable to run W2-61's scorer.
   - Inside such a session, a `git add -A` or `git commit -a` would record the acceptance tests as deleted (loses work).

   Today's base has no sandbox layer for (c) or (d) at all.

4. **Options.**
   - **(a) Re-baseline the sandbox clause** (DEC-105, re-baseline). (c) and (d) are enforced by the guard, on every tool and Bash read route an honest agent takes. The launcher adds no `Read` deny rule for them, and keeps refusing a launch under a malformed `evaluation_sets` block. The held-out `Read` rules (b) stay, since nothing needs to run them.
     - Consequence: a program the session runs can still open the files, which needs an opaque interpreter used deliberately. That is a Wave 3 hardening row (DEC-801).
     - Cost: one engineer iteration (drop `read_denials` for (c) and (d), about 30 lines) and a test-designer batch that rewrites W2-58's launcher cases to "no Read rule for (c)/(d)" with a Rewrite-Reason. Then the lead's full verification and the reviewer: about 3 to 4 hours.
     - Risk: low. It changes the words "and by its sandbox" in KPIs 1 to 3 and in DEC-821 items 1 and 2.
   - **(b) Apply strictly.** Keep the OS-level denial and run tests from outside the session: a broker that runs `pytest` outside the sandbox and returns only names, results and failure messages, or the lead runs them.
     - Consequence: KPI 1's "can still run" and KPI 3's scorer need that new channel. Test designers cannot import changed code in rewrite rounds.
     - Cost: high (new launcher and broker machinery, W2-56's or W2-21's scope), and every ticket's loop slows.
     - Risk: medium.
   - **(c) Defer.** Ship (a) now. W2-56 (which makes `gov launch` usable for every worker) takes as an entry criterion an OS-level (c)/(d) layer with a runner channel, if the owner wants one.
     - Cost: as (a) now, plus a row.

5. **Recommendation:** (a), with the Wave 3 row of (c) for an OS-level layer. Confidence: high.
   - Classification: Ordinary work: yes, because every launched engineer, test designer and measured session meets it on its first test run. Consequence: other: it blocks work, and loses work through a `commit -a` of the phantom deletions. It does not fail open: the guard refuses every ordinary read route, and its 563 acceptance cases pass.

6. **What it blocks, and what waiting costs.** It blocks W2-58's last engineer iteration, the review and the merge. Every start after W2-58 waits with it (DEC-857), and the read refusals of DEC-849 stay in force until it lands.
