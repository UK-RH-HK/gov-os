# P-W2-L423-Q — Row W2-L423's early warning stops every close after the first re-pin: it flags W2-69's own indexed files, which the pinned check passes

- **Priority:** P2 (it gates the close queue: all seven ready closes). **Raised:** 2026-10-26 21:35 GMT, by the orchestrator, after the first re-pin's smoke test (DEC-922).

## 1. Context

- Row W2-L423 (DEC-911): the gitleaks default rule reads a bare 40-hex string beside one of two keywords as a token, so a full commit hash beside a keyword under `.gov-runtime/` turned the secrets-indexing check red.
- DEC-911 (b) added an early warning, `tools/keyword_warn.py`. It lists, by path only, every file under `.gov-runtime/` that holds a keyword. The close queue runs it after each rebuild and stops before the close on any hit; gate (b) is the backstop.
- W2-69 ("the secrets check reads what the stores hold: no chance red from where a scan begins") is now pinned (DEC-922).

## 2. What happened

- **Before the re-pin's rebuild,** the warning listed 0 files.
- **The first full pinned rebuild** (2026-10-26, exit 0) indexed the tracked files that W2-69's merge brought in. The warning now lists 3 paths:
  - `.gov-runtime/codeintel/files/docs/research/W2-69-secrets-scan.md`
  - `.gov-runtime/codeintel/files/tests/acceptance/W2-69/test_w2_69_word_internal_fragments.py`
  - `.gov-runtime/store.db`

  These are the index's copies of W2-69's own research note and acceptance test, which hold the keywords on purpose: they test the case.
- **The pinned `gov check` on the same stores:** exit 0, secrets indexing GREEN (`log/repin1-smoke-gov-check-2.json`).
- **So the warning no longer predicts gate (b).** After every rebuild it would stop the queue before the first close, although the check passes. The files are tracked, and the rebuild indexes them every time.

## 3. Why it matters

No close can run through the queue while the warning stops on these paths. All seven ready closes wait: W2-70, W2-69, W2-66, W2-72, W2-59, W2-65 and W2-73.

## 4. Options

- **(a) Recommended. Scope the warning to what DEC-911 is about.** That is the files sessions write under `.gov-runtime/`: scratch, logs, briefs, returns, records and the like.
  - It leaves out the index stores' copies of tracked files (`.gov-runtime/codeintel/files/`, `store.db`, `query-vector-cache.db`), which the pinned check (W2-69) reads correctly.
  - The check itself is not changed, scoped or allowlisted. Gate (b) still runs before every close and fails closed.
  - Cost: a few lines in a scratch tool. Risk: low. A keyword written into a store by a session is still caught by gate (b), at the cost of the time the warning would have saved.
- **(b) The queue logs the warning's paths and goes on; gate (b) decides.** This is simpler, but the warning no longer stops anything in the queue. `record_checks.sh` keeps printing it.
- **(c) Keep DEC-911 (b) as it is.** No close runs through the queue until the warning is changed or W2-71 brings its exemption.

## 5. Recommendation

(a). Confidence: high.
