# P-W2-57-PATHS (draft) — the close's serial phase cannot reach the list's nightly route from W2-57's paths

1. **Context.** W2-57's KPI line 3 (DEC-889 item 5, P-IS-6) moves the live and real-model files out of the close to the nightly: the close's selection still collects them, but they run in neither the parallel nor the serial phase; the nightly (`tools/nightly.sh`: the parallel run less the list, then every list entry alone) still runs them. The route chosen goes through the serial-only list (the test designer's file): an entry of the nightly kind. W2-57's `allowed_paths` hold `src/gov/close/serial.py` (new: "the serial phase and its reasons") but not `src/gov/close/command.py`, whose `_run_tests` reads the list (`serial_only.entries(root)`) and gives every entry to the serial run afterwards.
2. **What happened.** The plugin (`gov_close_serial_only`) already keeps every listed entry out of the parallel run, nightly ones included (collected, then deselected). The one missing step is that the close's serial run afterwards takes only the entries that are not of the nightly kind. That is a call in `command.py` (about 2 lines: read the entries through `serial.py`, which tells the nightly kind apart; name the nightly entries left out in the run's stated record). No path of W2-57 reaches it; no test-map key does either (the schema has no such key and `select.py` is outside the paths too).
3. **Why it matters.** Without it the live and real-model files stay in the close's serial phase (W1-46's network reds refused W2-63's close; about 270 s of serial time per close, I-SYNTHESIS §2.4), and the 23 W1-46 entries and W1-19's warm p95 entry cannot leave `load_sensitive` (KPI 8).
4. **Options.**
   - (a) Widen W2-57's `allowed_paths` with `src/gov/close/command.py` (the serial phase's call to `serial.py` only), by the orchestrator's ticket-file commit (`Task: DAEO-cy5o`). Cost: one commit; a short run 2 (one engineer, a full verification, a review). Risk: low; command.py is shared core either way (`src/gov/close/**`).
   - (b) As (a), but the plugin (`src/gov/close/pytest_plugin/gov_close_serial_only.py`) tells the kind in the serial run instead. Cost: the same; risk: the plugin must stay stdlib-only and is also the nightly script's reader, so a change there touches the nightly.
   - (c) Leave the live files in the serial phase (today's state) and drop the nightly route from W2-57. Changes DEC-889 item 5 for W2-57; W1-46's 23 entries stay.
5. **Recommendation: (a),** confidence high. Classification: "Ordinary work: yes; Consequence: other" (fails closed: refused closes on network reds; time).
6. **What it blocks.** Only part of W2-57: the nightly route's last step and the removals that wait on it (W1-46's 23, W1-19's warm p95). Everything else (the probe and its four effects, the doctor probes, the list's reasons, W1-16 and W1-50 to parallel, the revisions) goes on.
