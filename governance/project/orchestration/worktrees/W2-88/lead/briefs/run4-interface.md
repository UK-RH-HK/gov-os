## The interface for run 4 (binding; stated by the lead from the ticket's `## Interface additions (P-W2-88-B-1)`, DEC-1157 (3), (12), and review round 1's triage, DEC-136; DEC-1052)

Each item: the behaviour, then how a case plants it. Names below are the interface; nothing else about the code is promised.

- **B-1.1 + B-1.3, the copy step (S16, S11).** Stage A9 copies, byte for byte, into the adopted repository:
  - every file of Gov OS's `template/governance/kernel/skills/retrieval/` to `.claude/skills/retrieval/` and of `template/governance/kernel/skills/discovery/` to `.claude/skills/discovery/` (same relative names);
  - T-0 `template/governance/kernel/templates/brief.md` and T-8 `template/governance/kernel/templates/role-cto.md` to `governance/kernel/templates/brief.md` and `governance/kernel/templates/role-cto.md`;
  - Gov OS's `governance/project/retrieval.yaml` to `governance/project/retrieval.yaml`, **only when the repository tracks none**; a repository's own tracked `retrieval.yaml` is kept as it is and judged (B-1.4).
  - The skills and templates are always written as Gov OS ships them (nothing re-worded per repository). The copies are committed in A9's own record commit (one commit), and the files are in place before the build and the scale/measure queries run. On a refusal of A9 the copies are not left in the tree (a refusal writes nothing in the repository's tree).
  - A9's record (and its result) holds `installed: [{path, sha256, from}]` (`path` relative to the adopted repository, `from` relative to Gov OS) for each file written, and `kept: [{path, sha256}]` for a repository's own `retrieval.yaml` (empty list when none).
  - The standard is judged on the `retrieval.yaml` in force: the repository's tracked one, else the installed copy. So a fresh adoption with no `retrieval.yaml` and no `--decision` is ok (no pool departure).
  - Plant: a planted adoption through A9; read the files and A9's record.
- **B-1.2, the reranker and the bundle are the pin's constants (S11, F7).**
  - A `retrieval.yaml` in force holding a top-level `rerank` or `bundle` key is refused `CONFIG_INVALID`, the key named in the message (and in `details["keys"]` when A9 raises it), before any store is built; a `--decision` does not make it ok. (On the CLI path `gov.config.loader` may refuse it first with its own `CONFIG_INVALID` naming the key: either is the decided behaviour.)
  - `fabric.settings_of(doc)` reads `reranker` from `gov.retrieval.rerank.MODEL` (its last `/` part), `bundle_tokens` from `gov.retrieval.retrieve.BUNDLE_BUDGET`, and `reranker_service` as `"shared"` when `(gov.retrieval.rerank.CACHE_REL, gov.retrieval.rerank.SOCKET) == (".cache/gov-os", "rerank.sock")`, else the string `"<CACHE_REL>/<SOCKET>"` (a second reranker). `widen` is `"sections"` (no constant to depart).
  - Plant (in-process): monkeypatch `gov.retrieval.rerank.MODEL` (e.g. `"Org/Other-Reranker"`), `gov.retrieval.rerank.SOCKET` (e.g. `"private.sock"`) or `gov.retrieval.retrieve.BUNDLE_BUDGET` (e.g. `4000`); then `fabric.departures(doc)` holds `{setting, value}` for it, and `fabric.read_standard(root, [])` raises `STANDARD_DEPARTURE` with the setting in `details["settings"]`; with `["DEC-1"]` (or `["DEC-1:<setting>"]`) it returns the block with `departures[*].decision == "DEC-1"`.
- **B-1.4, the pool (RV1-1; S11, F7).** The standard's pool is the whole `pool:` block as Gov OS ships it (`fabric.STANDARD["pool"]`). A `retrieval.yaml` in force whose `pool` differs from it in any key (a value changed, a key missing or added, or no block) is a departure `{setting: "pool", value: <the file's block, or false when there is none or meaning_uncut is not true>}`; A9 is not ok (`STANDARD_DEPARTURE`) without a `--decision` naming it. Plant: `fabric.departures({"pool": {**shipped, "route_depth": 5}})` names `pool`; the CLI path with that file in a planted adoption refuses.
- **B-1.5, the secrets scan not run (RV1-3; S2).** When the secrets scan did not run (no `gitleaks` on `PATH`) or skipped files (blobs over `assess.SCAN_LIMIT_BYTES`, 16 MiB): MA still writes `memory-assessment.json` and the `RP-*.md` proposals it finds; it writes **no** `NOTHING-TO-REFACTOR.md`; it writes `refactor-plan/PLAN.md` holding the line `secrets: not scanned (<reason>)` and the unscanned paths (or `all <n> tracked files` when the scanner did not run); and its result is not ok, error code `SECRETS_UNSCANNED`, `details` `{reason, unscanned}` (exit non-zero). The repository is still byte-identical before and after (F1). Plant: MA with a `PATH` that holds no `gitleaks`, on a repository with one secret line.
- **RV1-2, a vector scan that did not run (S5).** `scale.vector_scan_ms` is a figure only when the semantic route answered `available: true`; when it answered unavailable (`available` not true) or raised, `vector_scan_ms` is `null` and `scale.vector_scan_reason` names why (the route's `reason`, or the error's name). A null scan is never compared with the budget and writes no `SCALE-PROPOSAL.md`. Only the vector scan is compared with the budget (the routes' times are recorded, not compared); DEC-078's envelope figures still write the proposal when over. The scan is taken through `fabric.vector_scan(root, question) -> dict` (the semantic route's reply), the seam a test may replace in-process, as `fabric.search` is. Plant: a planted adoption with no query embedder (or `fabric.vector_scan` replaced by one returning `{"available": False, "reason": "FACET_UNAVAILABLE: planted"}`) and `--budget-ms 1`: `vector_scan_ms` null, the reason named, no proposal; replaced by one that answers `available: True` after a sleep over the budget: the figure recorded and the proposal written.
- **RV1-4, binaries the store holds (S3).** A file is never in a store's `refused` while that store holds it. A tracked binary the lexical index chunked is in `stores.lexical.indexed` (and in `stores.vectors.indexed` when it has vectors), and the store's block names it in `binary_held: [paths]`; the reason `binary` stays for a binary the store did not take.
- **RV1-5, the code graph (S3, F2).** With the code graph called for: a file whose suffix is not in the graph's languages (`assess.CODE_GRAPH_SUFFIXES`) is refused `unsupported-language` and never indexed by it; a graph that cannot be read makes `stores.codegraph` `{"built": false, "error": "<reason>"}` and A9 not ok, `FABRIC_INCOMPLETE` with `"codegraph"` in `details["not_built"]` (never nodes 0 and edges 0 with ok). Plant (unit seam): `fabric.check_coverage({"stores": {..., "codegraph": {"built": False, "error": "x", ...}}}, tracked)` raises with `codegraph` in `not_built`.
- **RV1-6, a load does not make a stale store current (S10, F3).** `gov.store.loader.load` stamps a store only when `gov.store.layout.check` finds it current (or the store is new); after `load` on a stale store (e.g. unstamped with `lexical_chunk` lacking `parent_id`, or stamped 1), `loader.connect` still raises `STORE_LAYOUT_STALE` with the same `details["found"]`.
- **RV1-7, the evidence (S7).** `docs/changes/W2-88-evidence.md`'s proof (a) states plainly, per repository, when no vector scan was measured (null, with the reason), and never calls an unavailable route's reply a scan time.
- **RV1-8, the no-route rule (S1).** The rule, stated once in `assess.py`'s text and in the evidence: a file whose suffix is in `assess.OTHER_CODE_SUFFIXES` (a code language the graph does not read) is `no_route: unsupported-language`; that list holds at least `.vue`, `.ps1`, `.proto`, `.svelte`, `.cob`. Plant: MA on a repository with a `.vue`, a `.ps1` and a `.proto` file: each is in the assessment's `no_route` list as `{path, reason: "unsupported-language"}`.
- **Accepted seams (unchanged):** `fabric.RETRIEVE_BUDGET_MS = 2000` (provisional) with `--budget-ms <N>`; the sixth refused reason `not-indexed`; A9's question set only by `--questions <file>` (no default).
