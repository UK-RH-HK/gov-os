# W2-96 design note, run 2 addendum (DEC-970), behaviour only

The design note and review 1's addendum (R1 to R7) still hold, except where this addendum differs; where they differ, this holds.

- **R8 (any failed case fails the run; DEC-970, PKG-1 (a); stricter only).** The run's `outcome` is `fail` and `gov accept` exits 3 when any collected case failed or errored, whether a README line maps it or not. A case the README never names is still only counted under `unmapped` (passed, failed and skipped counts), never named. `outcome: pass` and exit 0 now need both: every mapped line passes, and no case anywhere failed or errored. Skipped cases never fail the run. The rest is unchanged: a mapped line still fails when no case maps to it or when one of its test items matches nothing (R5); a run error is still `error` with its kind only and exit 4; a refusal is still exit 1. This replaces the earlier "unmapped cases never change the exit code".
- **R9 (Ctrl-C during the clean-up is held back too; review 2's N2).** A SIGINT that arrives while the clean-up runs (stopping the child, restoring permissions, removing the private folder) is held back exactly as SIGTERM and SIGHUP already are: the clean-up finishes, nothing of the run stays in the `TMPDIR` the caller gave, and only then does `gov` end. A second or third signal of any of the three kinds during the clean-up changes nothing. A Ctrl-C while the child runs still ends the run as an interrupt: the child and everything it started are stopped and the private folder is removed before `gov` exits. Nothing of the tests' content is printed in any of these paths.
- **R10 (the clean-up without recursion; review 2's N5).** The private folder is removed whatever its depth: a test that leaves a chain of more than 1,100 nested folders (some of them without permissions) does not turn a finished run into a `crash`; the run is reported as its results say (pass, or fail with exit 3), and nothing stays in the caller's `TMPDIR`.
- **R11 (an inherited "ignore" is kept; review 2's N7).** A signal among SIGHUP, SIGTERM and SIGINT that `gov accept` was started with set to "ignore" (as `nohup` does for SIGHUP, and a shell does for SIGINT in a background job) stays ignored for the whole run: that signal neither stops the run nor its child, and the run completes and reports as usual.
- **R12 (the exit after a signal; review 2's N8).** Whenever a SIGINT, SIGTERM or SIGHUP ends the run (during the run, or held back during the clean-up and acted on after it), `gov` ends by an ordinary exit with code 128 plus the signal's number (130, 143, 129): a parent process sees that code, never a death by the signal (`-2`, `-15`, `-1` in Python's `subprocess`).
- **R13 (the command is recorded; DEC-970, P-W2-96-CMDLIST (a), DEC-747).** `accept` is one of the recorded `gov` commands: the product's record of recorded commands names it (beside `ci`, `launch` and `telemetry`), and the acceptance tests' command lists name it too (W1-07's support list and its pinned list; W1-32's pinned set). `gov --help` offers `accept`.

## The README map forms the reader takes (for KPI 6's brief change, the orchestrator's at merge)

- Row form: a table whose header has a column titled `KPI…` and one titled `Test…` or `File…`; each body row maps the backticked items of its Test/File cell to the line names at the start of its KPI cell.
- Heading form: a table with a `Test…`/`File…` column and no KPI column, under the nearest heading that begins with line names (`### KPI 1: …`, `### S2 — …`, `### Failure 3 …`).
- Line names: `success N`, `S N`/`SN`, `KPI N`, `K N`/`KN` (success line N), `failure N`, `F N`/`FN`; several joined by `/`, `,`, `;` or `and`.
- Items: `file.py` (every test in it), `file.py::test_x`, `::test_x` or `word::test_x` (that test name anywhere in the folder), a bare word (`x` or `test_x`).
- Refused: no README or no mapped row (`ACCEPT_NO_MAP`); a row with items whose KPI cell names no line the reader takes, or a Test/File table under a heading beginning `success`, `failure` or `KPI` that names no line (`ACCEPT_MAP_UNREADABLE`).
- Not read (and so, since R8, a failing test there still fails the run): a table with no `Test…`/`File…` header (headerless rows, a `Case` column).
