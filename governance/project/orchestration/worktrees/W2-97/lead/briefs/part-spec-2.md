
### Changes to the specification in run 2 (DEC-985, DEC-983; these lines hold where the text above differs)

- **`enqueue --repo <repo>`** (P-W2-97-ENQ-1 (b), DEC-985 item 1): `enqueue` takes `--repo <repo>`, default the current folder, and resolves `--commit` there to its full id. A commit it cannot resolve there is refused (non-zero exit, nothing written) unless it is given as a full 40-hex id. A test that enqueues a short id passes `--repo` naming the planted repository.
- **KPI 1 as DEC-983 changed it: the run takes a heavy-job slot, not a test lock.** The production default run (the parallel run, and the selected serial-only cases after it) goes through the machine's heavy-job slots: each of those two test commands is run as `bash /home/usain/Dynamic-Agentic-Engineering-OS/.gov-runtime/scratch/orchestrator/tools/verify_lock.sh <the command>`, which waits for one of the slots, caps `-n auto` for it, and exits with the command's own code (DEC-979 D1). The single-process "alone" re-runs and the traces run freely. A `--test-cmd` stand-in replaces the whole run command, slot included, and is run as given (so the slot is not observable through the stand-ins). There is still no shared test lock; the queue's own `run.lock` (one writer) stays.
- **KPI 3 as DEC-983 changed it: the full suite never runs here, only in the nightly.** The queue runs only a selection whose `scope` is `scoped`. A selection that answers any other scope (`full`, `refused`, or anything else) cannot be used: nothing is run, nothing advances, nothing is ejected for it, the entries stay approved, and `run` exits 4 with the reason on stderr (for `full`: the full suite runs only in the nightly). This is rule 8 above ("a step that cannot be done").
