### Group A: `gov close` (`src/gov/close/**`)

1. **The probe gate (DEC-505).** A merge commit that brings exactly the probed code into the integration branch does not count as "after" the probed commit. Commits that change the ticket's code after the probed commit still refuse, as today. What "exactly the probed code" means is the test designer's to state from DEC-505, DEC-498 and the gate's cases, stricter where in doubt; the orchestrator's residual notes and probe record, committed after the merge outside the ticket's code, are the case DEC-505 was written for: say in a package whether your reading covers them or leaves them refused, and build the stricter one meanwhile.
2. **`gov close` calls the counter (DEC-495, its fourth point).** The close record is written first and the governance share is measured after it; the caller supplies the session ids; with none supplied, or with the counter unable to measure, the record says "not measured" by name and the close is not refused for it. The counter outputs counts only. No real session log of this machine is read by any test or worker: only the specimens the telemetry suite holds.
3. **A refused close prints each test run (DEC-566).** The JSON of a refused close carries the same per-run figures a passed one does (form, workers, counts, time, the cases set apart), whether or not a test failed.
4. **Findings of this ticket's last probe (DEC-555).** (1) A run of the declared cases that ends with exit code 0 and no result is a finding, whatever the parallel run passed. (2) A file of the project named like the close's own plugin cannot replace it: the close's plugin is loaded, or the close refuses. (3) Parallel workers end with a run that is cut at the time limit; nothing of that run writes into the project after the close returns. (4) A list entry that names an existing file without a case refuses, as DEC-549's fourth point says. (7, first shape) a byte in the list that is not UTF-8 is a refusal with its own finding, not a traceback.
5. **The repair ticket of a refused close with long findings.** Today the findings go to the ticket tool as one argument, and a close with very many findings ends with "Argument list too long" and no repair ticket. The repair ticket is opened whatever the findings' length, through the ticket tool as before (no ticket file written by other means); what is cut, if anything, is said in the ticket and in the output.
6. **The owner-decision lookup (DEC-483).** The escalation path finds the owner's decision in a decision file or in an entry of the register file the project names (DEC-473's grammar), not in decision files alone.
7. **The trailers base commit (DEC-482).** The trailers check gets the same kind of base-commit setting as the citations check (DEC-474, DEC-479): a project may record a trailers base, only commits after it are judged, with none the whole history, and a base that is no ancestor commit is a finding of its own. The key's name is the test designer's proposal beside the two existing keys; **this repository's own path map is not edited by you** (the orchestrator writes the key at the merge).
8. **The close record's skills list in a project with an installed kernel (DEC-521).** Read W1-30's residual on it in the bootstrap file; the record lists the skills and their versions where the kernel is installed under `governance/kernel/` and not only where it lies under `template/`.
