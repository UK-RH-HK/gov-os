- Ordinary work: yes, because every worktree launch on this machine loads it.
- Consequence: other. The OS write list is not widened (step 0 refused; the mounts show it), `--settings` role and ticket win, the guard confines file-tool writes, and `GOV_DEV_TIERS` names a synthetic dev set.

**R2 — The exclude lines are permanent and repo-wide** (`sandbox.py:29-31`, `:130-131`). Scope: in (S4).
- They have no slash, so they ignore a new untracked regular file at those names at any depth, in the main checkout and every worktree, after the session ends too. `git add -A` silently leaves such a file out. CIT-E §6 names this.
- Ordinary work: no, because the repository tracks no file at those names at any depth, nothing in `src` generates one, and a sandboxed Bash cannot write those names.
- Consequence: other (an explicit `git add <name>` reports that the path is ignored).
- Would be reversed by: a ticket that legitimately creates and commits a file at one of those names.

**R3 — A killed test run leaves its daemon folder behind, and the sweep doesn't cover it** (`codeintel/__init__.py` `make_session_base`; `tests/conftest.py` `_own_cbm_base`, `_without_tool`). Scope: in (S1).

- Ordinary work: yes, because killed runs happen.
- Consequence: other (small leftover folders on disk).
