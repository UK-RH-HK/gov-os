## Findings

### F1 (failure-5): a short gold span is "held" by a member that does not hold it

`_normal` strips a leading `key:` (`_KEY = ^[A-Za-z_][\w.-]*:`) and list marks, then `_match` tests `text in held`
with no word boundary and no minimum size. A gold alternative in a family member whose span is one short line
normalises to a few characters, and any item anywhere in any member of that family that contains those characters
counts as a hit. Probe on the branch code (gold span → normalised → item → result):

- `docs/contract/contract.yaml`, one line `    floor: 85` → `85`; an item of `CONTRACT_v4.md` reading "DEC-850 set the
  review at 1985 lines." → **family**.
- `contract.yaml`, one line `  - id: CAP-1` → `CAP-1`; an item of `capabilities/CAP-10.md`, "# CAP-10 Retrieval" →
  **family**.
- `status: open` → `open` against `owner: open` → **family**; `DEC-1078: the owner accepts option A.` against
  `DEC-1079: the owner accepts option A.` → **family** (the `DEC-nnnn:` prefix is taken for a key).

The member's text does not hold "floor: 85", "id: CAP-1" or "DEC-1078: …" in any formatting, so these are failure
line 5's case. Reach: the question form accepts `lines: [n, n]` and a non-`#` `heading` with no `lines` (one line,
`_span`), and the "exact strings and identifiers with file and line" category invites a one-line cite; the 24
visible questions' in-family golds all span 2 or more lines or a section (checked by path and lines only), but the
hidden halves, written by other authors, I did not and may not read. On the contract family (`CONTRACT_v4.md` is
large and dense in ids and numbers) such a gold would be hit by almost any contract item in the first five,
inflating hit@5 and full evidence on the very half that decides K9.

Ordinary work: yes, because an honest set author citing an exact value or an id by file and one line is the form
the measure documents and the set's categories ask for; nothing deliberate is needed.
Consequence: fails open (a hit counted that the evidence does not support; the measure overstates).

Fix, small, in `measure.py` only (fails closed): give no family hit for a gold whose normalised text is under a
floor (e.g. fewer than 4 words or 24 characters), and match on token boundaries (pad both sides with a space, or
compare word lists); optionally keep the key, lower-cased, instead of dropping it. Add one unit row per probe
above. A cheap check for the CTO, counts only: how many hidden gold alternatives in a family normalise below that
floor.

### F2 (S7): a family glob joins distinct sources, not only a source and its copies

`kernel: ["template/governance/kernel/**", ".claude/**", ".rulesync/**"]` makes every role, skill and hook one
family, and `docs/contract/capabilities/*.md` every capability page. An item from another role's file holding the
same line counts as a hit on the gold role: probe, gold `roles/engineer.md` "- **Tools:** Read, Grep, Glob and Bash"
against `.claude/agents/independent-auditor.md`'s longer Tools line → **family**. Role and skill files share
boilerplate lines. The text rule holds (the member does hold the gold's text), so this is not failure 5; it is the
family's breadth. The path map follows S7's own wording ("the kernel template and its generated `.claude/` and
`.rulesync/` copies", "the generated `docs/contract/capabilities/*.md`") and the CTO's interface (1), a list of
globs, which cannot pair a file with its copy.

Ordinary work: yes, because a boilerplate line shared by role files is a plausible one-line gold.
Consequence: fails open (rarely: only where two distinct sources carry the same text).
Scope: out (S7's own design of the families, the CTO's interface (1)); a row: a paired form (a member's copy found
by a path mapping, e.g. `template/governance/kernel/roles/X.md` ↔ `.claude/agents/X.md`) for the CTO to weigh, or an
accepted limit. F1's fix narrows it.

### F3 (S7, `--kept`): a re-score on a pre-S7 clone applies no family, and says nothing

`families()` reads the sets root's path map, else the measured root's. The kept runs were measured on clones at
pre-S7 commits (`measure_verdict.sh`: `--root $CLONE --sets-root ~/gov-os-eval`); unless the sets root's own path map
declares `evaluation_families`, `--kept --root <that clone>` re-scores with no family, and the text output has no
line saying which families (if any) were in force; only the JSON's `family_hit_count` key shows it.

Ordinary work: yes, because the CTO's planned re-score of every kept run is exactly this call.
Consequence: other (fails closed: the figures as before, which could be read as "families change nothing"; no hit
invented, no work lost).
Fix (a row, rides with F1's fix): one header line, `families: <names> from <path map>` or `families: none`; and
the re-score note in the ticket says the families are declared in the sets root's path map.
