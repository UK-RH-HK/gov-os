  run exactly as today. `cut = None if meaning_uncut else (depth or semantic.TOP_K)`: with nothing set the cut is
  `semantic.TOP_K`, read at call time as before; the file route's `cut` equals the old value. `span` moved earlier with

  The unit tests compare the bundle byte for byte and the reranker requests for absent, `{}`, all 0 and 0-as-false,

- **Equality with the harness.** The head is `fused[:n]` filtered to chunks the lexical index holds (`_fusion`'s

  item's lines are in the kept one.

Findings:

- **F1.** `retrieve.py`, the pool block: a pool rerank that returns unscored is not retried; the page is left in the
  fused order and `rerank.by` says `unavailable` with the reason. The harness would score the page again. This is the
  engineer's stated gap. It is bounded: the failure is reported (S4's rule), the next search asks again, and the same
  failure on today's path also leaves the fused order. The CTO's measure runs with a live reranker, so v456's equality is
  not affected unless the service fails during that measure.
  Ordinary work: yes, because a reranker can fail or time out in a normal session.
  Consequence: other (a degraded, reported order; nothing is lost or silently wrong).
- **F2.** `retrieve.py`: `per_file_first10` is applied before S8's routing (`named_first`, `code_first`), where the
  harness's `_final` applies `front` and `pin` before the cap. With S8 routing on, a routed hit moved to the front can
  leave more than n chunks of one file in the first 10. With S8 off, or without per-file, it does not arise. It is
  declared in the evidence row and is outside what v456 measures; the CTO's measure with S8 on shows the size of any
  effect.
  Ordinary work: yes, because both settings can be on in a project.
  Consequence: other (a ranking difference from the harness's order, nothing lost; every chunk is kept).
- **F3.** `pool.settings` casts with `bool(...)`/`int(...)` on values the loader has already validated, so the cast is
  safe. No finding. (Recorded to show it was checked.)
