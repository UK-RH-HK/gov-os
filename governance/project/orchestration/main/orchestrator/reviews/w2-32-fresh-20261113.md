## Judgement rules (JUDGEMENT.md, word for word)

- **The threat model is ADR-0001's** (`docs/adr/ADR-0001-threat-model.md`): the Gov OS guards against honest agent mistakes, plausible accidents and drift in ordinary work, not against a deliberate adversary with the owner's privileges. Machinery against an adversary the design cannot stop produces endless review loops.
- **Every finding is judged by two questions, word for word:**
  1. "Can an honest agent hit this in ordinary work?"
  2. "Does it fail open or lose work?"
- **Only a finding with "yes" to both justifies a round.** A finding that needs a deliberate construction (a link planted at a protected name, git environment variables set by hand such as `GIT_OBJECT_DIRECTORY` or alternates, replace refs, an opaque interpreter used to evade the guard) is a row for the Wave 3 hardening pass, never a new round (DEC-801). A finding marked "no" on the first question is a row automatically.
- **Every finding in a probe or audit record carries two lines:** `Ordinary work: yes|no, because …` and `Consequence: fails open|loses work|other` (DEC-808).
- **No extra round on its own:** when a ticket will resume anyway, its accepted fixes ride along in that resume (DEC-802).
- **Feature-gated risks:** a risk that exists only when a feature is switched on is an entry criterion of the ticket that switches it on (DEC-803).
- **Packages:** every package that proposes a round states the classification of its findings on one line, before the recommendation (DEC-809).
- A finding blocks only if it is in scope, reachable in ordinary work, and fails open or loses work (DEC-1010).

**F1. S1: the real-model swap's dev-tier regression is on no record.**
- What happened: S1 says the dev-tier retrieval regression passes after a pin change. The acceptance cases prove
  it on a stand-in second embedder with planted questions.
- What is missing: the README hands the real swap to "a measured run on the CTO's record", and the evidence row says
  only "the CTO's run (real embedder)". I found no such run in the evidence file, the LIFT-1 packages or the D4B
  records. The embedder pin has not changed since ADR-0002's.
- What should be: a recorded run of a swap to a real second model, then `retrieve_check`'s dev tiers. Otherwise
  the close note should name the line as met on the stand-in only, by the CTO's ruling.
- Ordinary work: yes, because closing on the stand-in alone, with the real run named but never made, is the ordinary
  path.
- Consequence: other. The re-embed and the fail-closed pin are tested. What is missing is a record, and nothing opens.
- What would reverse it: a committed record of that real-model run, or a ruling that S1's regression is the planted
  stand-in one.

**F2. S3: a regression case is kept out of the vectors but not out of the keyword index.**
- What happens: `record` writes the case, with its question, gold answer and sources, under
  `fixtures/memory-quality/cases/`. The semantic route never embeds that folder. The keyword index leaves it out only
  where the path map says so.
- Where that holds and where it does not: this repository's path map says so (`evaluation-fixtures`,
  `lexical_policy: not indexed`). The template's path map has no such rule. In an adopting project, a later measure
  that asks the case's question could find the case file, with its gold answer, by keywords.
- What should be: the case held out of both indexes by the code, as the vectors already are, or the template's path
  map carrying the rule.
- Ordinary work: no. No command records a miss (only the library call `learning.record` does), and this repository
  is covered by its path map.
- Consequence: other. It could flatter a measure in an adopting project. No guard opens.
- What would reverse it: a template or adoption step that puts `fixtures/memory-quality/**` in a namespace that is
  not indexed, or a reading that S3's "held out" means only "not embedded" (the interface's words).

**F3. S7: a superseded rule is still stated (DEC-1067 (f), superseded by DEC-1090 (2)).**
- What is stated: the ticket's body ("reranker requests capped at 16 texts", DEC-1067 (f)) and the README's S7 and
  S8 test names (`..._more_than_16_texts...`, `..._within_16_texts...`) state the 16-text cap.
- What is in force: DEC-1090 (2), through W2-137, raised the cap. The code has `MAX_REQUEST_TEXTS = 64`, and the
  cases were revised in `0cb8ba995` to read the cap in force while keeping the padded bound.
- Why it matters: the code follows the decision in force. The ticket's text does not.
- Ordinary work: yes, because a reader or a brief that takes the cap from the ticket takes 16.
- Consequence: other.
- What would reverse it: the ticket's note and the README re-worded to DEC-1090 (2)'s cap, or a decision that put
  16 back.

**F4. S11: the speed clause is not met as measured. Owner-level.**
- What the line says: "a plain search's median stays at or under the pin's, measured by the CTO on the shared
  servers, the pin and the candidate side by side in re-pin window 4" (DEC-1086 A).
- What was measured: the side-by-side measure is PAT-1 §3, 2026-11-07, 10 questions, 3 passes each, interleaved.

  (2) raises the request cap for concurrency. The evidence row records no speed figure. No later measure of a plain
  search alone with the pool on is at or under 1.44 s: M3-ADOPTION-1 §3.3 still gives 1.68 s, and at W2-137's cap
  only the concurrent figures were measured.
- Ordinary work: yes, because every plain search pays it.
- Consequence: other. It is a speed cost: no guard opens and nothing is lost.
- Not blocking (DEC-1010). The line is not met as written, so it goes to the owner once, with options (DEC-105):
  - (a) Re-word the clause to the measured and accepted cost: the pool on within about 0.25 s of the pin's median

  - (b) Keep the clause and measure again on today's pin with the cap at 64. Cost: one short window of about
    20 minutes. It may well still be over.
  - (c) Defer the clause to the memory audit's speed watch. Cost: none now. The line stays open.
- What would reverse it: a side-by-side measure with the pool on at or under the pin's median, or an owner decision
  on the clause that I did not find.
